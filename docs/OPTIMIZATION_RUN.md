## 铁律

优化不得改变任何可观察行为。判定标准不是「我觉得等价」，而是下面三条之一：

1. **测试证明** —— 新旧实现对拍，逐位相等；并且用**变异测试**证明该用例
   真的会失败（改坏实现能让它变红）。绿灯但杀不死变异的用例等于没有用例。
2. **测量证明** —— 有基准数字，前后都测，只保留真的更快的。
3. **类型证明** —— 删代码后 `tsc --noEmit` 干净，说明确实无人引用。
   `grep` 不算引用检查（本轮已经栽过一次，见 `e0c9633`）。

任何「看着像能合并、实际语义有差」的东西一律不碰，并在提交信息里写明
为什么不碰 —— 否则下一个人会重新踩一遍。

### 迭代 1（2026-08-25 晚）

| commit | 内容 | 实测 |
| --- | --- | --- |
| `6b24b13` | 形态学二值快路径（滑动计数） | open 352 → 201 ms |
| `3b981fd` | 形态学位图化（倍增扩张 + De Morgan 腐蚀） | open 201 → **87 ms**，累计 **4.0×**；k=31 与 k=5 同价 |
| （本条） | 搜索索引小写化预计算 | 每次击键 3.0 → **1.1 ms**（2 万条目） |

**位图形态学的测试覆盖是分三轮才补齐的**，每一轮的缺口在绿灯下都看不出来：

1. 宽度只到 23，`wordsPerRow` 恒为 1，`spreadCols` 的跨字进位从未执行 ——
   而真实编辑器描的是 3000px 宽的 mask。现在宽度刻意横跨字边界。
2. 整字位移仍是死的：倍增只有在 reach 超过 63（即 r ≥ 63）时才会吐出
   s ≥ 32，远超编辑器 25 的核上限。
3. 把 k 提到 200 仍然覆盖不到 —— mask 比 reach 窄时扩张会铺满整行，
   丢掉整字位移看不出来。必须 w ≫ reach，所以另加了一条 300×9 / k=141。

变异验证：丢弃跨字进位、`wordShift` 归零、`clearTail` 空转、`spreadRows`
只向一侧、倍增差一 —— 五种全部能让用例变红。

**搜索**：`search()` 每敲一个字符就全索引扫一遍，循环里对每条目做三次
字符串分配（`n.toLowerCase()` / `cn.toLowerCase()` / `srcCode().toUpperCase()`）。
改为随索引构建一次。存成**并行数组**而非挂在 Entry 上，因为合并后的索引会被
序列化进 localStorage，给每条目多塞两个字符串会白白撑大那份缓存。键按索引
**对象身份**绑定而不是长度 —— 两个不同索引可能条目数相同，用错键会静默返回
错误结果。

### 迭代 2（2026-08-26 凌晨）

第二轮普查覆盖了此前没 profile 过的 6 个区域（dice / statusTracker / bubbles /
initiative / bestiary+人物卡 / 共享设施），46 项发现。**主导模式只有两个**：

1. `onChange` 回调把 OBR 刚递过来的数组扔掉，然后再去全量重取一遍；
2. 同一个常量（网格 dpi、玩家 id/角色、场景 metadata）在循环里逐 token / 逐帧重取。

| commit | 内容 | 实测 |
| --- | --- | --- |
| `4b832a0` | 传送落点搜索网格化 | 58.3 → **12.4 ms**（4.7×） |
| （本条） | `Intl.Segmenter` 提到模块级 | 0.112 → **0.034 ms**（3.3×） |
| （本条） | 标签渲染的语言按「一次渲染」缓存 | 一次法术描述数百次 localStorage 读 → 1 次 |

**落点搜索**为什么能精确等价：两个安全判定问的都是「有没有**任何**一面墙不合格」，
网格返回的是可能不合格的墙的**超集**，被剪掉的墙可证明不可能不合格。两个判定各用
各的查询框 —— 一个是候选点周围的小圆盘，一个横跨整条视线 —— 用同一个大框会把剪枝
效果丢掉大半。几何部分抽到了 `portals/landing.ts`，穷举版保留为对拍基准。

**语言缓存**刻意只作用于**一次同步渲染**（`formatTagsClickable` 入口设置、`finally`
清除），而不是模块级常驻 —— 后者会让运行中切换语言失效。用 `finally` 是因为渲染中途
抛异常不能把陈旧值钉死给后续所有渲染。

**这一轮明确没做的**：所有「复用 onChange 已递来的快照」类改法。它们看着最诱人，
但 `scheduleSync` 之类的合并逻辑会让快照比重取**更旧**，而且很多调用方根本没有快照。
不可证明等价，一律不碰 —— 理由写在各自的提交信息里。
