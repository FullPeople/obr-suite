# 2026-09-27 三龙活跃牌局主持移交

实施于隔离源码 `F:/CodexWork/2026-09-27/feedback/suite`。本轮不提交、不推送、不发布；不能把此记录当作真实枭熊多人验收。

## 原因与完成的行为

原自动接任只适用于大厅；活跃局的完整牌库、私牌、行动收据和历史仅存于主持浏览器的 IndexedDB。只修改房间公开 metadata 的主持身份会失去可继续的游戏状态，不能用公开广播私牌来弥补。

现在原主持可以在工具栏选择“移交主持后离开”。已有主持 `leave` 命令也走同一流程。接收者必须在线且已建立认证私有会话，优先 GM（允许未入座），否则按座位顺序选择玩家；普通未入座旁观者不接任。活跃局保留所有座位及各自私牌，只迁移主持权限；大厅的离席可以移除原主持座位。

移交先通过现有 ECDH/HKDF/AES-GCM 私有链路发送完整存档，接收者验证房间、桌子、版本和游戏不变量，成功落盘后才回复认证确认。原主持再次核对公开版本，再写入公开主持身份。metadata 不包含完整存档或私牌，普通广播只有现有加密数据包。超过单条私有消息上限的存档按 8,000 字符切片，累计最多 4,000,000 字符。移交期间暂停其他变更，避免私有快照与公开版本不一致。

收据丢失会重试同一移交，不重复存储、重发资源或重新发牌；接收者存储失败保留原主持与游戏；公开身份写入失败保留已存档的候选状态并允许重试。主持改变后重建私有会话，继任者通过原恢复路径读取刚收到的完整存档。没有在线适格接收者时，不假装完成移交。

同时修复未入座 GM 的全能显示：`canEdit` 仅表示当前持有权威存档的主持，不能据此撤销其他 GM 的查看权限。UI 改为核对主持/GM 身份；主持按实际接收者投影私有视图，普通玩家请求仍拒绝；成员降权时撤回其全能视图并发送普通投影。跨主持迁移清除旧全能授权并重新认证。

## 尚未验收的边界

- 必须主动点移交并等待完成再离开房间。突然断网、关闭浏览器或在移交完成前强行离开，不承诺自动转交；原浏览器完整存档恢复仍沿用已有机制。没有后台同步所有私牌至全部参与者。
- 关闭 UI 面板只返回地图，不等于离开桌子；后台主持继续运行。
- 活跃局原创建者的座位和私牌保留，移交不会自动弃权、代打或删除其座位。后续游戏裁定由主持处理。
