# Full Suite-dev 1.0.172 · 同步冲突诊断与背包状态效果

## 171 之后仍失败的原因

用户报告“该条目已被修改，请重试”。此错误来自三方合并的数组删除校验，不是 171 已修改的库存转移校验。

最小复现：已保存的 condition.raw 没有 _suiteStatusId；网页从文档恢复并补充此编号；无棋子或棋子尚无状态 metadata 时，宿主仍使用原始行作为当前值，直接与带 UI 标记的 previous 比较。数据没有被他人修改，删除仍被误拒。旧浏览器用例始终保留完整棋子状态，未覆盖该分支。此次已加入“删除状态 metadata 后移除”和“整枚棋子移走后移除”两种浏览器路径。

修复将原生角色文档也纳入 observed/previous/next 投影合并：按稳定行 ID 比对真正观察到的原始数据，保留其他行的并发新增。对象键顺序不视为变化；真实远端修改和删除仍拒绝覆盖。状态 hydration 以存储的最新层数优先，避免客户端旧副本掩盖远端调整。

没有证据表明实际服务在重排字段；这只是额外消除的比较不稳定因素。没有改动实际角色 API 或清理用户数据。

## 诊断

- 同步冲突包含条目 ID/名称、字段路径、删除或修改操作、最多 12 处前后差异。
- 所有宿主失败确认附带 dev 版本、时间、请求 ID/类型、失败阶段、HTTP 状态（若有）和受限栈信息。
- 错误 toast 提供“复制同步诊断”；提示倒计时结束后，角色卡底部继续保留最近一次诊断的复制入口。
- 只复制诊断，不导出整张角色卡或连接凭据。字符串截短，凭据字段脱敏；剪贴板不可用时显示可手动复制的文本。

## 背包

背包外框、物品格和空格接入共享框体艺术和重力。保留圆角；石化裂纹、隐形虚线、中毒、力竭分段与恐慌边缘动画覆盖这些格子，其他整卡效果自然叠加。

重力分两层：背包整体与页面其他框碰撞；内部格子在背包区域内独立堆积，避免父子框被当成同层碰撞对象。下落移动真实命中区域，编辑模式回位；新增格子会重新参与计算。怪物与公共仓库不继承玩家角色的状态特效。
