# 骰子诊断按实际构建包选择检查

本候选基于已合并书籍阅读的 Suite `f1796af7eb6fedb3b4f151114c57945f08ed9cb2`，仅处理第 38 项 CI 诊断入口。尚未合并或部署，玩家投骰源码、当前轻量模式、版本、发布入口和权限保持。

## 失败证据

`Verify released dice resources 246` 在书籍合并前的 `669cc6c`（运行 `39469641261`）和合并后的 `f1796af`（运行 `39477293052`）均有四组任务失败；两份浏览器日志在相同的 120 秒物理渲染就绪等待点超时，骰子源码与该工作流在两次提交之间没有变化。

实际产物进一步确认原因：同次运行的历史物理基线完成时序检查，并留下三十五条基线像素记录；当前版本的 SDK 探针已到 `ready`，打开的却是 `workbench-dice/overlay2d.html`。旧诊断仍等待只属于 3D 路径的状态事件，因此未进入当前版本的像素／时序对比。主 Suite 验证、多人与权限检查已经通过，不把这解释为玩家 2D 投骰已失败，也不把旧 3D 专项称作已验收。

## 候选处理

新增必经的实际构建包检查，使用主 Suite 验证现有的精确配对 Web `a17685f` 构建完整开发包。

- 物理包必须先通过原有完整生产包校验，包括来源提交、配对 Web、资源锁、文件摘要和未插入诊断代码等条件；随后仍执行原四组物理检查。
- 轻量包必须有四份完整入口及对应程序，入口摘要须与程序字节一致，也不能带有无生产清单的物理文件；随后执行现有轻量浏览器检查，覆盖四个模拟客户端、权威结果、重复请求、暗骰隔离、表达式、外部面板、卡住的远端请求，以及零物理 worker／WASM 请求。
- 缺文件、旧摘要、未知或不完整构建直接失败。只有适用检查通过后才向工作流输出模式；检查过程中还核对提交、已跟踪源码和实际包均未改变。
- 原四组任务的步骤、断言、时限、物理基线及其配对 Web 保留。当前轻量包会明确显示这四组不适用而跳过；手动运行时可显式要求继续执行保留的物理诊断，原有失败会照常暴露。

没有调整安全权限、凭据、分支保护或发布审批，也没有用 `continue-on-error` 忽略失败。

## 验证阶段

十三项原创构建边界检查通过，包括空包、缺少程序、字节变化、额外入口、未标识物理文件和无效物理清单。实际完整构建、现行轻量浏览器、最终精确提交 CI 尚待核验。此处的受控 SDK 和浏览器检查不代表真实房间、实体设备或历史 3D 画面已经验收。
