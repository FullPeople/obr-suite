# 恢复新版工作台的资料导入和订阅入口

旧设置页已有本地 JSON／Markdown 导入和单文件 URL 自动订阅。新版工作台重组设置分类时，漏掉了原“库设置”分类；全局搜索分类只保留两个开关和怪物来源控件。数据模块仍在，但用户找不到导入或订阅入口。修复前的真实编译设置页在 GM 身份下找不到 URL 输入框，原五秒断言失败，记录保留。

候选恢复原“库设置”分类，完整复用原页面和原事件处理。GM 可管理已有库、导入本机文件、添加原始 JSON URL、刷新和移除订阅；玩家保留原只读范围。全局搜索的怪物来源控件继续保留。沿用现有 IndexedDB、来源校验、刷新失败保留缓存及更新事务，没有新增另一套来源或存储协议。

实际编译页面回归使用原创资料和独立浏览器，覆盖 URL 添加、原生文件选择、更新失败、重试、更换内容后无重复、重开、无关本机文件保留、390px 入口及玩家只读。在提交 `44309b163dda70b148401d66a5ef2de953d18dce` 上，七组实际页面流程、既有五组怪物来源控件、类型检查和 68 组完整受控回归全部通过；三张桌面、窄屏及玩家只读截图已逐张查看。首次夹具把本地行与订阅行混为一个定位器的失败保留，后改为明确核对本地行数量和文件名，没有放宽条件或时间。完整配对构建、准确提交 CI 和合并后检查另列；受控 SDK 夹具不代表真实房间或玩家原设备验收。

该入口修正不改变已回放的 25 个原生资料消费文件，也不改变 Web／Data 的 77 个规则绑定文件。最终使用哪份现有回放，仍须核对完整来源字节和冻结输入；未解析资料、上游失效地址及玩家原格式缺失继续单列。当前未部署，邮件和私人资料没有进入仓库。
