# Full Suite 176 同步权威与回归

本轮只复用原来的角色文档、库存账本和枭熊 metadata，不引入第四份存储或新服务。

## 数据从哪里来

- 完整角色 JSON（含头像、规则快照、背包投影）在角色服务器 `characters/<room>/<card>/data.json`。它支持无棋子仍可打开的角色。
- 角色当前生命、状态、资源以角色 JSON 为持久权威。棋子的原 HP / status / resource metadata 键继续提供场上渲染和兼容其他原功能的编辑入口。
- `com.obr-suite/workbench/runtime-baseline` 记录棋子上一次被投影的运行态及角色文档 revision。未改动的旧棋子回到场景时只接收新角色数据；与基线不同的实际场景编辑按字段/资源/状态增量并回文档。
- 怪物没有角色 JSON，仍以其 metadata 运行态为准。
- 库存的位置和数量继续以一个房间库存 CAS 账本为准，原子完成公共与私人背包间的移动，再投影进角色文档。

## 证实的故障路径

1. 旧代码无条件让 token metadata 覆盖角色 JSON。无棋子时移除状态或修改资源，旧棋子回场便会将旧值反写。现在记录投影基线，未变化的旧数据不会成为新编辑。
2. 1800ms 定时器先发 refresh，随后 repair 升 epoch 作废该 refresh；repair 结束没有恢复待刷新任务。没有本地交互的另一个宿主可能每一拍都被打断。现在 repair finally 恢复等待中的刷新。
3. 普通角色保存无 statPatch 时仍将旧导出 JSON 的全部 HP / AC 回写 metadata。现在只提交明确修改，原生运行态与文档保持一致。
4. 旧库存 repair 拿到旧 ledger 后异步写文档，期间新的移除操作可能已完成。现在库存写和角色投影通过中继共用房间串行锁，并在锁内校验 ledger revision。旧投影在写入前被拒绝。
5. 场景直接清除状态时，库存授予的同一状态行可能仍留在账本。现在导入实际场景移除时同时退休该 grant，repair 不会复活它。
6. 异步 GET 可在更新提交后返回旧文档；库存读写回应也可能交错。角色 `_suiteRevision` 与库存 revision 均不许缓存降级，丢失广播可由 1.5 秒 freshness 读取恢复。
7. 怪物没有角色 JSON，资源和属性编辑改为对 OBR 回调中的当前 draft 做三方增量合并：不同资源不互相覆盖，同字段发生冲突则保留最新值并报错。
8. metadata 投影延迟时，更新回调核对角色 ID、基线 revision 和读后是否发生真实编辑；不会覆盖另一宿主较新的投影。

角色 catalog 与 selection 均传递 `documentRevision`，完整文档使用 `_suiteRevision`。网页端也需按此版本拒绝旧运行态，不能仅使用连接内消息 sequence；连接刷新后 sequence 会从头开始。

已有旧角色首次接入（revision 0）采用其现有场景运行态并建立基线。已有现代文档（revision > 0）遇到没有基线的旧棋子时采用文档。对首次迁移前已经发生且没有版本信息的历史冲突，程序无法还原真正的先后；没有声称可以恢复丢失历史。

## 检查

- `tools/workbench-runtime-176-selftest.mjs`：13 组。旧投影、旧无标记棋子、旧格式导入、独立字段合并、冲突字段、状态增量、运行态往返、最大生命 / AC 原生修正及不改动无关计算，库存读写回应乱序缓存防护，怪物不同资源/属性的现场增量合并及同字段冲突拒绝。
- `tools/workbench-176-sync-selftest.mjs`：15 项，真实 background、relay、CAS server，2 个独立浏览器宿主，SDK 边界模拟。覆盖无棋子编辑与旧棋子返回、外部 metadata 编辑、漏广播、延迟读、双宿主延迟 OBR 回调、退休库存状态授予、旧库存投影服务器拒绝、双宿主同时修改怪物不同资源。端口独立 5397/5398。
- 原库存同步 9 组、合并 8 组、库存事务 4 组与 TypeScript 编译通过。
- 原通知浏览器 19 项通过：消息内容、声音、准备/取消、失败保存不通知、重复投递去重、旧角色结果不能反盖降权后的隐私规则。
- 实际枭熊跨设备房间尚未实测，模拟通过不等于实机验收。
