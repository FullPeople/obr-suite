# 183：连续修改不重复下载刚提交的整卡

182 已将角色文档确认与 token 投影拆开，但每次 resource/stats/save/condition 命令仍调用 `read(a, true)`。第二笔命令即使有本机刚成功提交的完整权威缓存，仍先发起整卡 HTTP GET。另有运行状态修复、库存广播与 grant 收据清理会在主命令路径等待与持久提交无关的 SDK 回应。

本次命令使用有效的最新缓存；收到远端变更时仍失效缓存，服务端原有 SHA/CAS 并发校验不变。未经通知的远端修改仍拒绝冲突写入，不以旧缓存覆盖。无可用缓存时正常读取文档。

已提交后的 token 修复、目录/库存广播、grant 收据清理不阻塞命令确认；怪物仅 metadata 持久化等必要写入仍等待成功。通知采用已有玩家身份缓存，避免再请求一次玩家名字。
