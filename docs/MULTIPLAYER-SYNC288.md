# 多人同步优化 288

本批只修改工作台调度、共享库存重试和 Relay 有限请求额度。规则、资料与骰子权威计算保持原实现，QQ 云卡撤权与 6 秒授权过期保护继续独立生效。

Relay 对已知小请求保留有限接收额度；大请求仍限制并发与累计正文大小。存储读取与写入分别使用有限并发、有限队列和等待期限，普通消息转发不占存储位置。断开的等待请求不会继续开始写入，已开始写入的结果仍需核对。

相同客户端重试握手时重发当前状态，合并正在进行的刷新，避免再次初始化全部卡。普通数据事件短窗口合并，选择事件与授权变化立即处理。库存投影仍每 4 秒修复，全卡条件读取每 30 秒补查漏掉的广播。

库存只重试已明确拒绝的 409；12 次尝试及约 3 秒重试调度预算。每次都读取新修订，再按原操作 ID 合并，保留权限和未知结果核对。单次网络请求仍使用现有超时，不能把 3 秒当作端到端完成保证。

验证包含实际库存模块与真实本地 Relay 的十卡 1／4／8 个模拟参与者、慢保存与即时消息隔离、CAS、重复操作、未知回执、权限与内存。受控浏览器验证不代表真实 QQ 扫码或真实多人房间验收。
