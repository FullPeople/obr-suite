## 必测矩阵

- 实际物理数量 1 / 2 / 5 / 9；10 为边界正控，不修改原 100 枚功能上限。
- d4/d6/d8/d10/d12/d20、百分骰（d100 为两枚实际骰子）、混合形状；五种当前皮肤。
- 冷启动首次准备、已就绪首投、暖连续投、上一投尚未落稳、两个来源同时投、手机/平板接收桌面权威轨迹。
- 手机 320×568、390×844、横屏 844×390，平板 768×1024 / 1024×768；DPR 1/2/3；投掷途中和结果阶段旋转/resize，临时 0/1px 容器。
- 长负数结果、长名字、五行公式；结果、名字和关键动画可读、可见；透明层不拦截原页面操作。
- UI 安全区、系统浏览器工具栏/软键盘、真实 Safari/WebKit 和 Android Chrome 必须另测，纯 CSS viewport/Node 几何不是设备验收。
- 私投 self/gm/players、旧客户端、刷新重连、丢清单/丢尾包/迟到/重传/慢 SDK ACK、clear/场景退出/上下文恢复。

每个样本分段记录：点击→SDK 请求接收→权威开始预测→轨迹完成→编码/排队/上传→各端验证与准备→计划开播→第一帧包含可见且姿态改变的骰子→落稳→结果。分别记录 P50/P95/最大间隔、冷准备成本与总演出时间。CPU WebGL 提交、GPU 读回、最终屏幕呈现须分开，不将提交当成显示。

## 已证实的限制

当前权威先预测完整物理，再传递和验证完整轨迹。已有结果必须与轨迹、私投权限一致。新投掷把旧骰最终落点用作碰撞体，所以上一投未落稳时仍需等待其物理落稳。删除这个等待会制造视觉/碰撞不一致，不能作为此小修。未知网络、冷加载和隐藏/丢失上下文均保留真实等待。

本机真 Node Worker / 锁定 Jolt / 生产 gzip，18 个暖样本每档：1/2/5/9/10 枚物理中位约 9.0/13.0/28.4/50.5/77.1ms，最大 13.5/21.5/47.0/164.0/264.0ms。运行于 AMD EPYC 9V74、Node v24.19.0、本地资源；不代表手机、浏览器或线上网络。1/2 枚均一片，5 枚一至两片，9 枚两片，10 枚两至三片。不能从数量推断消息一定能装入一包。

## 本地最小修改

实际少于 10 枚、非群体分组且全部已冻结接收方明确支持时，将同一首片 7000B 放进清单消息。一片轨迹省独立数据片与结束提示两次排队；多片仅省首片的独立排队，后续片与结束提示保持原流程。完整 JSON 信封及所有定向重试均检查 15000B 限制。单片协商 `inlineRollV1`，多片另用 `inlineChunkV1`；旧客户端、仅支持单片的客户端、群体、10枚及以上和超大小信封维持原协议。

重用同一 Assembly/SHA/decode/身份与私投检查，仍等真实准备 ACK。恢复用的 offer 重发携带同一首片。重复片仍做冲突检测，但只有新片更新进度时间，避免每秒重发首片把丢失后续片的 NACK 一直推迟。

同时修正审阅发现的既有刷新竞态：发送期间对方重启导致该投掷被撤销后，不允许原异步处理继续开播，或继续生成已经撤销的后续群体子项。

小屏几何补丁详见 `DICE-SMALL-VIEWPORT-20261004.md`，音频依赖补丁详见 `DICE-AUDIO-REQUIRED-20261004.md`。
