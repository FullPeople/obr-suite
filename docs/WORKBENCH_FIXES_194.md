## 问题、原因、改动

| 反馈 | 本轮处理与证据 |
| --- | --- |
| PL 无法打开编辑模式 | 用户补充明确是 DM 导入完整备份后把棋子交给 PL。原权限逻辑在 `owner_ids` 非空时忽略棋子所有者。现在有效归属为卡内显式所有者与当前绑定棋子所有者的并集；临时棋子授权不写回目录，转交后撤回。没有把“公开可读”放宽成“任何人可编辑”。真实 SDK 边界模拟验证了玩家实际保存、私有卡不可见、转交后拒绝旧玩家写入。 |
| 怪物 HP 泄露到播报 | `statNotices` 对无角色文档的怪物排除当前、临时、最大 HP；保存和场景血条继续更新。资源、状态和人物播报保留。 |
| 2014 全身掩护显示成 3 | `{@quickref 掩护||3||全身掩护}` 第三段是索引，第五段才是显示文字。抽出按标签解析的 `inlineLabel`，正文、预览、纯文本导出共同使用；quickref 可按基础词条跳转。 |
| 主卡法术更新／法师没有准备栏 | 旧枭熊导入器依据“当前是否有已预备法术”推断制度，空准备栏被当成学习制，且缺少职业施法声明。对旧导入记录，只从唯一匹配的同版本源条目补回缺失施法字段；已有声明、手动制度覆盖和自定义内容优先。恢复预备公式／表格，法术书与准备栏区分。主卡依实际预备状态显示，戏法与兼职的学习制法术保留。 |
| 法术导出误标预备 | 实测发现缺少 `spellSettings` 时旧导出将所有已学法术当作预备；现使用有效设置与实际预备引用，未预备仍留在已学列表。 |
| 导入版本／来源冲突 | 导入前列出版本差异、禁用条目、原记录等级与当前计算等级。取消不创建角色；继续保留原条目与等级，不自动替用户开启房间规则。单机保留被导入角色自己的版本，房间遵守房间规则。 |
| 兼职开关失效 | 第二个不同职业经过 `candidateReason` 检查兼职选项；已存在的兼职记录不会因关开关被删除。个人自定义职业也走同一检查。 |
| HP 只有平均值 | 编辑模式点击生命值标题，可选固定平均值、逐级骰值、手填基础上限。首个角色等级满骰；兼职各自记录，体质随属性计算，原有卡面调整仍独立。支持备份往返。 |
| 子职定位 | 点击子职空框直接展开职业的子职内容；`class` 引用携带子职参数时定位子职本身。 |
| 独立分类搜索 | 每个 Wiki 分类独立保存搜索词；切换、刷新保持，全局搜索不改变分类搜索。 |
| 自定义内容无法自由填写 | 编辑模式新增“条目 / 等级”，直接录入职业、子职、种族、背景、特性、专长、法术、物品等；已有个人自定义内容可修改。个人卡内内容无需修改 DM 的共享资料库，明确禁用仍有效。 |
| 高等级创建繁琐 | “条目 / 等级”集中填写各职业目标等级，无需逐级点击。原有明确声明特性按目标等级整理；没有引入写死的熟练项配额和逐步向导。 |
| 同步中卡住 | 修复上面的实际归属拒绝；阅读共享卡不再自动写回特性／施法迁移，实际编辑才提交。异常时工具栏出现“同步核对”，能强制重读服务器结果、复制诊断及导出本地修改；重读不重放写请求。无法确认的写入仍保持备份，不盲目重试或丢弃。 |
