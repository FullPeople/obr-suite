# Full Suite-dev 1.0.171 · 状态与背包同步修复

## 复现与根因

用户路径：向角色卡加入状态，再拖出移除，提示“背包条目已经转移，请刷新后再编辑”。使用原同步函数、模拟共享文档持久层复现了相同错误。

原 syncNative 把 item 与 condition 一起视为库存条目，以角色选择 ID 查库存行。来自棋子 metadata 的状态没有库存行；Wiki 状态经过 hydration 后增加 _suiteStatusId，和库存中原始条目也不再逐字相同。因此状态正常删除被误判成物品已转移或更新。

同一审计发现：库存写入成功、角色文档写入失败后的重试不幂等；旧快照修改可复活远端已删除行；补偿投影及网页 hydration 把状态层数写回 1；状态的不同来源编号未统一。

## 修复边界

- 原生角色卡状态使用运行时状态身份，不要求或新增库存行。已有旧库存状态、公共仓库给予的状态在移除时清理对应授予记录，避免补偿任务重新加回。
- 状态身份集中映射，兼容 Wiki、棋子 metadata、共享状态目录及旧库存编号。授予投影去重，保留力竭等现有层数。
- 库存仍只在原容器内修改；真实物品已经转移后的过期编辑继续拒绝，不采用“跳过所有找不到的行”的修补方式。
- 重试同一物品新增、数量调整、删除和货币写入可重复执行。独立字段合并，同字段冲突拒绝；已被远端删除的对象不复活。
- 成功保存并确认角色卡反映完整库存结果后，仅确认相同 revision 的补偿记录；失败或尚有其他待授予内容的记录保留重试。
- 不清空既有角色、库存、公共物品或本地备份，不自动删除用户备份。
