# 2026-10-03 follow-up candidate

This independent candidate preserves the published monster lifecycle release 237. It does not merge or deploy the official branches.

## Changes

- Startup presentation owns its actual image, animation, final-pose and fade lifecycle. Card content and automatic notices wait for completion. Reload, failed startup, stale bridge clients and BFCache restoration retain an explicit lifecycle.
- Three Dragon labels use each seat's full physical anchor. Completed-game exit returns to the local main screen; new and already-running legacy transports preserve other participants and archived games. The Suite entry fills its plugin viewport and restores the previous workspace/focus on close.
- Character AC uses rule calculations plus explicit offsets. Scene totals cannot create absolute overrides. Existing overrides have an explicit, evidence-preserving recovery path in armor settings.
- Selected source text in the bounded armor-conditional AC rule family contributes only while body armor is worn. Source ownership, duplicate suppression, removal and unsupported rules remain explicit; this does not claim universal feature automation.
- Attribute editing presents the stored base before native selection/first paint while normal display remains the total. Read-only trace inspection and keyboard navigation remain available.
- Top-level entries/levels and correction buttons are removed; legitimate lower-level configuration remains accessible.
- Dashboard drafts confirm discard and await persistence. Styling includes background, zero/default or adjustable borders, corner radius and compact spacing. Actual module footprints can shrink; fields round-trip through the card, overview and Suite presentation. Concurrent resource use is preserved.

## Validation and release boundaries

Run the repository's full existing verification plus the new startup, table, armor and dashboard suites. The candidate CI retains all existing monster-lifecycle checks.

Local Chromium cannot launch in this cloud sandbox because its socket operation is denied. Browser visual/focus/first-paint verification is therefore executed by the candidate's GitHub CI; local compilation/test discovery is not browser acceptance. Synthetic room boundaries are not real authenticated Owlbear multi-account verification.

The Three Dragon service change rejects a mismatched optional gameId before any Leave mutation. Client reconnection protection works with the new frontend; protection against an already-in-flight stale Leave additionally requires publishing that service change. No service deployment is performed by this candidate.

Legacy completed-game exit changes local presentation only, preserving historical membership and private archives. A new legacy game displays normally. No room reset or player-data deletion is used to return to the main screen.
