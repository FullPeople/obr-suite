# 2026-09-27 · 199 怪物图鉴循环引用热修

用户报告 `Converting circular structure to JSON`，路径为 `__ → props → children[1]`。在已发布的 198 生产构建中原样复现，属于产品代码错误，不要求用户删卡或清空资料。

## 原因和修改

部分原始怪物 `cr` 是对象，例如 `{"cr":"1/2","lair":"1","coven":"2"}`，而不是字符串。列表预览直接把该对象交给 Preact 的 `CR {monster.cr}`。Preact 将它当成节点并写入父节点引用；对象同时仍属于原始怪物，后续 `_copy` 继承的 JSON 拷贝因而报循环引用，IndexedDB 也可能因对象中混入 DOM 引用而写入失败。

现在资料解析阶段把列表 CR 归一成文字，支持字符串、数值（包括 0）、对象中的普通 CR、特殊说明；未知值显示问号。原始资料仍保留完整的普通/巢穴/共巫等级等字段，供详情、继承和保存使用。没有通过跳过 JSON 报错、删掉继承怪物或吞掉循环引用来掩盖问题。

同一 `data.ts` 用于新旧插件，两份构建都包含修复。枭熊公告增加简短说明，单机公告不写入这条枭熊修复。候选版本新版 `1.0.199-dev`、旧版 `1.3.8`、单机发布标记 `standalone-1.0.199`、公告 `0.1.8`；实际部署以后续回执为准。

## 验证

- 198 生产页面：先把对象 CR 的原型怪物显示出来，再放行延迟返回的继承怪物，稳定得到用户相同错误和路径；还捕获到缓存 `DataCloneError`。
- 修复后生产页面：7 种 CR 形态显示为文字；预览后继承加载成功；实际点击放怪后共享场景 JSON 保留完整 CR；强制刷新、缓存重载均通过，无脚本错误、循环引用或缓存写入错误。
- 原创测试索引提供固定 ETag，验证缓存重载不请求怪物数据文件；测试真正等待新一轮资料下载完成，避免把旧列表当作刷新成功。
- 真实上游生产页面：4559 / 4559 条，首次 111 个图鉴请求，缓存重载仅 1 个索引请求；两次无加载失败和页面脚本错误。控制页记录 1 条资源 404，不作为图鉴读取失败或全部图片正常的证明。
- 原有禁用来源依赖链、错误详情、重试、无效继承 4 个回归继续通过。TypeScript 与新旧完整构建通过。
