# 本地职业资料检索候选

该候选只影响新插件便捷搜索中已导入或已订阅的职业资料，依赖缓存事务保护候选。它不代表服务器发布、全部自制资料阅读器或新规则自动化完成。

## 问题与行为

原导入器只识别 23 类内容。只有职业数组的文件被拒绝；含物品、可选能力等数组的混合包虽然报告成功，职业、子职和两类特性仍全部缺席。旧文件正文已经保存在本地，单改新导入流程不能补出旧缓存中的分类。

新增四类索引，从当前保存正文派生分类和条目数，保留原文件身份及已有内容。新类别放在原有类别之后，保持混合包的原主类别和同名替换行为。完整远端搜索缓存继续可读，其本地部分按当前原文重建，覆盖旧版本缓存和同一 URL 刷新后文件身份不变的情况。

每个职业条目绑定资料包、分类、完整记录摘要及显式版本。姓名相同、英文名相同或等级相同不构成合并依据；旧选择失效时不会到其他文件或网络资料中寻找同名替代。2014、2024 和未标明版本分别保存；后者明确标记。没有修改旧角色卡或 Wiki 的资料编号。

详情展示原说明、职业／子职的特性清单及表格，解析同包同版的显式引用。来源 UID 的默认值与现有角色卡 Wiki 契约一致，子职来源独立默认为 PHB，能力来源默认归属其所有者。只有同包、同版、来源唯一且不含修改指令的基础继承会展开；其他继承、缺失依赖、多个候选和循环引用显示提示。原资料和选择保持原样。

## 验证与边界

- 八个原浏览器反例先失败，修复后通过；加入来源默认值、继承与循环、URL 刷新、未知版本后，共十二项通过。使用真实导入器、IndexedDB 和便捷搜索页面；宿主生命周期用受控替身隔离，因此不算真实房间验收。
- 十六项既有缓存事务、写入失败、并行窗口和迟到刷新检查通过，类型检查通过。完整 Suite CI 单独核验。
- 以公开来源清单的 240 个去重地址为调查基线，冻结 238 份可下载输入；两项上游 404 未用空内容冒充成功。开始和结束时的来源、类型索引摘要一致。此清单不等于已确认玩家邮件所指的全部约 200 个包。
- 原模块接受 191 个包，候选接受 210 个；索引从 11,582 条增至 21,133 条。新增职业记录共 9,551 条：职业 98、子职 875、职业能力 2,249、子职能力 6,329；2014 版 8,652 条、2024 版 899 条，完整引用身份全部独立。
- 所有 9,551 条在重开前后均能返回详情，无异常或空查找；其中 301 条带有依赖、正文为空、循环或无法唯一解析等提示，共 909 次。这是解析和可见性检查，不是逐条规则或人工正文验收。
- 另有 28 个可下载包的主体类型仍未支持，书籍、冒险全文及其他类别需另批处理。角色卡内 Wiki 的不同内容共用编号另行修复，不能通过整体重编编号破坏旧卡引用。
- 原始第三方正文、实际邮件及私有证据均未放入本仓库。公开测试只使用原创示例。新模块不属于规则执行器，不能用旧 Data 完整回放宣称这些自制规则已自动化。

## 集成与回滚

先集成缓存保护，再审查本候选，解决冲突后重跑完整检查。配对 Web、Data 锁定、来源开关和权限保持；部署仍须独立人工审批。回滚只需恢复插件代码，缓存格式未迁移，不清理玩家保存的原文。新类别在旧版本暂不显示，但原包内容保留。
