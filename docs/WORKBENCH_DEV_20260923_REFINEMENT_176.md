# Full Suite-dev 1.0.176 · 同步权威与窄屏查阅

## 本轮行为

- 同屏 Wiki 用正文预览；窄屏、卡片全屏时使用 tooltip。左键查阅，法术中键预备／取消；普通模式支持已学与预备区域之间拖拽及槽位交换。
- 单独禁用的资料在列表、正文、标题、嵌套段落与 tooltip 中均划线；未启用整个来源仍按来源配置隐藏。
- 子职导航默认收起，子职按钮切换显示；导航到子职正文不丢失该开关。
- 总览下从窄屏 Wiki 拖拽时临时显示功能页，松手回到 Wiki。资源列表按可用宽度显示三／二／一列，功能开关同样自动换列，公共仓库整条标题可折叠。
- 窄屏人物与怪物共用 A4 顶部对齐，上方横排页签，压缩周围工具栏。撤销左侧的卡片全屏在当前网页视口最大化，保留浏览器拆分视图；Esc 退出，点击查阅时恢复 Wiki。

## 同步边界

当前并不是把整张卡只保存在一个棋子 metadata 中：完整角色文档使用既有服务器角色文件，背包位置／公共物品使用既有库存账本；Owlbear metadata 是场上血量、状态、资源的可编辑映射。无棋子角色仍能编辑，所以不能仅依赖棋子。

本轮不增加服务或存储层。角色文档以单调版本作为运行态依据；metadata 保存已投影版本与基线，真实场景修改按字段差异合并。旧棋子、延迟 HTTP 响应、重连旧消息不能覆盖更新的文档。库存投影与账本检查共用服务器房间事务队列，旧投影被拒绝；场景清除状态也退休对应库存状态条目。修复周期性校准不断打断远端刷新的问题。角色卡读取原生文档时停止再次用旧 metadata 混盖状态和资源。详见 WORKBENCH_SYNC_AUTHORITY_176.md。

## 验证与限制

网页交互、窄屏与主从消息测试以及双宿主模拟使用真实应用代码，SDK／资料边界使用自制测试数据。真实 Owlbear 房间与实体平板尚未实测。以下记录本地验证，部署收据见文末；不把模拟结果视为真实房间验收。

最终本地验证：70 项单元，15 项网页交互／响应式／消息乱序浏览器检查，68 项完整工作台联动（29 次保存），15 项双宿主同步（14 次文档保存），19 项通知（12 次保存）通过；另有运行态／库存缓存 13 组、合并 8 组、库存同步 9 组、库存事务 4 组通过。TypeScript 与完整开发版构建通过。

254px 联动验证覆盖了人物／怪物等宽 A4、上方页签、窗口内全屏、总览拖拽临时切页和恢复、资源三／二／一列、功能开关多列与整标题折叠。修复了窄屏点击总览／骰子或选择棋子时未切回功能页的问题。

上线需同时发布网页、Suite background 与 relay；房间内使用者需要刷新枭熊和角色卡页面，避免继续运行旧宿主。首次无版本数据仍按现存场景迁移，不能恢复更新前已丢失的历史顺序。
