# Workbench 177 synchronization investigation

## Confirmed code paths and fixes

- `catalog()` previously awaited every character download and runtime reconciliation. A 1.5 s cache expired before the 1.8 s polling timer; `access()`, `snapshot()`, inventory projection and permission checks all called it again. Selection now has an independent path that reads only its target. Catalog uses cached summaries; background hydration fills them separately with in-flight deduplication and conditional ETag reads.
- A hydration pass retained `items` from before another slow character download. A status added and removed during that wait could later be merged again as an apparently new token delta. Runtime reconciliation now reads current scene items immediately before computing a delta and rechecks its observation before persistence. The inventory revision guard and token-draft guard remain.
- The standalone monster path waited for `loadAllMonsters()`. Stable installations could hide this latency by warming the same-origin caches or providing a scene snapshot. The workbench now calls `loadMonsterBySlug()` (target source and copy dependencies only), using the existing detailed loader and an independent request pool.
- Old bound cards no longer depend on a separate plugin initializing the scene list: validated bindings supply an owner/GM-only fallback entry. Explicit deletion tombstones still win. Legacy upload URLs are retained by the directory. A missing scene list is not treated as deleting the room directory.
- Inventory confirmation previously awaited card mirrors and scene notices. The atomic inventory ledger is now confirmed first; durable pending projections are repaired independently. The existing CAS protects projections against a newer ledger. Public warehouse locking is durable and enforced on every mutation, not only by UI.
- A 15 s client timeout used to reject and remove optimistic state even while a queued host mutation later executed. Requests now have an execution deadline, request-status receipts, in-flight deduplication and no mutation retransmission. Already-started writes can finish; expired waiting intentions cannot execute. Lost write responses use readback before any result is declared. Unknown outcomes preserve edits and block dependent queues until an actual terminal receipt or explicit reconciliation.
- Console controls and settings RPCs do not wait behind character writes. Server serialization is per character; only inventory-projected saves also take the room inventory lock. The public-message toggle uses the independent inventory path.
- Ordinary saves no longer upload unchanged portraits, rule text and packs in repeated previous/current snapshots. Three-way changed branches preserve concurrency checks, then relay applies a CAS-protected delta and sends the complete document through the existing Flask API. Legacy absent/null ancestor objects remain absent/null in the observed baseline rather than becoming manufactured empty objects during reconstruction. Large envelopes use gzip. No additional datastore or Flask API is required.
- Small heartbeats replace repeated full roll history. Catalogs emit only when data changes. A local opener bridge is preferred, with a separate direct-connection expiry and relay fallback. A same-origin, same-session ping can rebind the retained WindowProxy after the host iframe reloads; each direct mutation sends that ping first so the first edit receives confirmation. ACKs return through the requesting transport, including a copied relay window while the direct window is open.
- The original bottom-right dice-history popover is restored in persistent mode. Dark-roll filtering applies to restored history and role changes as well as live broadcasts.

## Validation and limits

- `tools/workbench-177-network-selftest.mjs`: 18 checks; real workbench controller behind an SDK boundary, including 12 s unrelated reads, 18 s writes, switching, console/message controls, duplicate requests, expiration, receipts, inventory confirmation, warehouse locks, delayed hydration, cold bound legacy cards, the persistent dice-history dock, and actual host iframe reload with the same WindowProxy followed by an acknowledged first edit. Final log: `workbench-test-output/network177-reconnect-final.log`.
- `tools/workbench-177-transport-selftest.mjs`: 12 checks (including absent legacy fields and missing/null race parent branches versus hydrated UI defaults). An actual relay request throttled to approximately 30 KB/s committed an approximately 200 B compressed HP delta; the previous full input for the same fixture was 1,024,715 B. Tests retain the 341 KB portrait, preserve independent edits, reject stale/prototype/unauthorized writes and recover a lost inventory write response without replay. Final log: `workbench-test-output/transport177-parent-shape.log`.
- `tests/mutation-queue-177.test.ts` in the Web repository: 4 checks for ordinary sequencing, known failures, and unknown-result blocking / terminal-receipt recovery.
- Existing 176 two-host and inventory-model regressions remain part of closeout. Full build, UI and deployed verification are recorded by the root task.

These are controlled simulations and code-path tests. They do not establish real-room or physical-tablet acceptance. An Owlbear host restart loses its in-memory command receipts; unresolved outcomes must be read back or explicitly reconciled, never automatically replayed.

Deployment must include `server/workbench-relay/patches.mjs`; the relay proxy timeout must allow the bounded long write/readback path. The existing Flask endpoints and card schemas remain compatible.
