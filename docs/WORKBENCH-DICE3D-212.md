# 新版骰子 212：加载、排版修复

范围只限 `/suite-dev/`。不修改旧插件、独立 Web Lab、角色卡 Web、阅读器、公告、服务器逻辑、数据库和 Nginx。

## 用户反馈及本轮变更

用户看到 `renderer: TypeError: Failed to fetch`，快速骰盘被两个新增选择框挤坏；随后要求二级骰盘和完整投骰面板在加载期间全部禁止操作，显示等待文案与实际进度。

1. 删除快速投骰、完整骰盘顶部新增的材质/可见范围栏。普通/暗骰沿用原按钮；材质只在原皮肤选项卡更改，不读取已删除的可见范围选择记录来改变普通投骰权限。
2. 两个工作台骰子页面共享固定定位加载遮罩，且底层内容 inert，键盘回车也无法误投。显示“正在加载骰子，首次渲染会花费一点时间，请等待....”、实际完成资源数/总数、下载字节及阶段。只在后台收到物理初始化和实际首次渲染成功后解锁；资源 100% 不代表已可投。
3. 音效、模型、字体与数字贴图采用同 URL Promise 去重、四个实际并行下载槽、最多三次同资源网络重试。缺文件/哈希错误不回退。共享音效只下载/解码一次，音效与模型初始化并行，不用延长提交等待掩盖加载问题。
4. 资源错误带 `E_DICE_ASSET`、具体路径、HTTP 状态/原始原因及次数；模型/音效解码错误保留路径。加载失败仍锁定，并提供“重新加载”。仅无已投记录的初始化失败允许重建物理层，不能借重试清空已有权威历史或重新掷骰。
5. 使用已锁定资产 manifest 和 Jolt 1.1.0 锁校验下载字节。真实 wasmBinary 交给引擎实例化，实际暖机和首次 shader 编译完成才发 ready，不假发完成。
