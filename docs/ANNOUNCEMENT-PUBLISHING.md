# Owlbear Suite / DND Card Web 公告发布要求

用户于 2026-09-27 明确要求作为以后遵守的记忆。

- 发布新批次时，最新公告展开；原有公告完整保留并默认折叠，不每次堆在首页或删除历史。
- 标题只用日期。同日多批采用“2026-09-27-一”“2026-09-27-二”“2026-09-27-三”；已有批次不重编号。同日原先合并的一份历史公告作为第一批，不虚构其内部发布时间。单批日期可不加序号。
- 内容按功能区域用中标题分组，组间用分割线。用玩家看得懂的短句：“增加了……”“修复了……”“现在……可以……了”。不写实现细节或夸大完成度。
- 单机网站、新版 Full Suite、旧插件、独立三龙牌分别核对适用范围；单机公告不混入 Owner、地图、三龙牌等联机功能。共用修复覆盖所有实际使用该模块的入口。
- 未复现、仅模拟环境通过、缺少真实房间/手机验证时写“待验证”；尚未修复写“仍在排查”，不能藏在历史“已修复”下面。
- 自动化规划、原型、待做事项不能写成已上线功能；不要使用“马上”“全部完成”等无依据承诺。
- 保留网站和新版的“我知道了”必点、下次版本前不提示、相关进入按钮；新版 Owner 说明靠前、默认折叠，红字标题“关于设置玩家单独权限的重要说明”。保留旧版新版安装完整可复制链接。
- 按用户需要同时提供可直接发聊天群的纯文本公告：无 #，用换行、符号和分隔线。
- 发布前核对当前 Git/线上版本，更新适用入口版本、公告确认版本、源码包；不从混合脏主目录整包发布。
- 验证各渠道最新/历史内容、默认折叠、展开滚动、手机窄屏、确认与版本记忆；部署后核验公网版本与实际资源，并记录回退点和未测范围。
- 服务器发布前备份，保护角色与牌局数据；不能通过删数据或清空未确认写队列“修复”问题。是否发布按当次用户授权，不从这份记忆推导持续自动发布权限。

当前实现入口：Web src/platform/releaseNotes.ts、src/ui/Announcement.tsx；Suite public/announcement.md 的 [release]/[history]。当前接手路径以 docs/AI_HANDOFF.md 和最新发布回执为准。
