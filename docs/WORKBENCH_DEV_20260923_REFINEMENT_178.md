# Full Suite-dev 1.0.178 · 同步根因修复候选

尚未部署，部署和最终校验由本轮收尾追加。1.0.177 的模拟通过不能覆盖用户现场失败；本轮明确将它判定为实机同步验收失败。

## 已确认根因和处理

- SDK 3.1.0 的 getRole/getSelection/getMetadata/getItems/party 皆为跨 iframe RPC。旧切卡串行 10～13 次往返并重复复制整景；改为首次读取和完整变更事件缓存、单次目录贯穿选择链。慢卡读取不持有选择锁，晚到结果不能改回旧卡；读取完成重新核对权限。
- SDK updateItems 使用 Immer 10.2.0 Proxy，structuredClone 资源行会直接抛 DataCloneError。用只复制 JSON 值的脱离代理拷贝，测试直接实例化真实 SDK。
- 导出 parsed_at 是生成元数据却参与了业务冲突。稳定导出值并按明确路径合并生成字段，真正 HP、资源和自定义同名字段仍冲突保护。
- 库存不变的属性/HP/头像/专长修改不访问库存账本；一般无变化通知也不读取账本。保存合并等待由450ms缩短至80ms。
- 文档/库存已经提交后，场景投影或播报故障不能回报整次修改失败；返回已提交回执与警告，展示投影待同步。只重试投影，不重放用户修改。
- 入口保持原生链接和标签页。左键建立连接后保存枭熊顶层窗口引用，背景刷新可以重新发现直连；心跳/重试不占布局。右键/复制无窗口关系仍有网络回退，两页同时全刷新不能保证 opener 直连。
- 骰子身份、角色、权限读复用 SDK 事件缓存；不同目标仍校验，玩家降权后不能隐藏或固定投骰。
- 点击连接状态可复制最近24条无角色内容的时间诊断，区分直连/中继、排队、宿主处理、保存/投影阶段。

## 测量与验收边界

300棋子、8角色的同一真实SDK/postMessage测试，40ms父窗接口延迟：切卡622→20ms，投骰382→52ms，二级投骰568→59ms。150ms时切卡约3ms，投骰约160ms。5次items事件从139 RPC与12.63MB全景副本降为0额外全景读取。慢卡6秒下载中切回缓存卡3ms，晚到下载不覆盖。这里测到的是选择消息和投骰广播，不是用户房间和WebGL动画落地。

独立RTC DataChannel科研证明无opener也能建立本机P2P（P95约2ms），未接生产。现有postMessage已经亚毫秒；复杂的新传输不能替代本轮真实瓶颈修复。

完整证据见 WORKBENCH_PROXY_178.md、WORKBENCH_SDK_PROFILE_178.md、WORKBENCH_TRANSPORT_178.md。真实多人房间、平板、不同网络仍需使用者实测，不宣称互联网零延迟。

## 最终消息顺序与故障回归

角色runtime按持久化revision独立于传输sequence合并，迟到但版本更新的ACK同时更新当前卡和总览，不恢复旧权限。怪物runtime按item各自排序；库存ACK不会吞掉角色目录刷新。后台catalog在等待共享资料期间若发生新事件则丢弃旧构建并重算。

真实SDK附加故障注入10项及网页乱序/80ms队列5项通过；SDK Proxy 9项、无关库存保存7项、完整联动68项、慢网重连18项、双宿主15项、未知结果恢复3项通过。测试以各自边界声明为准，真实房间尚待用户验证。
