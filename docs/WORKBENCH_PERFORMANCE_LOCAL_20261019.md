## 改动

- 启动时仍发布完整的有权限角色目录；正文只预读当前卡与前后相邻卡。没有有效选择时不扫描正文。
- 选择新卡时优先读取，不排在旧卡的后台请求后面。相同读取共用任务，尚未开始的旧邻居预读会被丢弃；已经开始的读取仍正常完成。
- 原生卡远端通知仅主动刷新当前窗口或已访问的卡；未打开的远端卡保留失效标记，打开时读取。权限核对、版本冲突、读取失败与保存确认沿用原流程。
- 网页同步的派生计算延后到现有 80 ms 合并窗口结束后。生命值、临时生命和已认证资源余额修改复用派生结果；职业、装备、规则和新传入的权威文档重新计算。队列保留最初基线与最后结果，不丢弃独立操作。
- 不修改 CSS、排版和角色文件格式。快照最近访问列表仍上限 24；本次没有引入整份文档的淘汰策略，不声称会话内所有内存均限制为三张卡。

## 本地复现

先完成网页规则回归和来源锁定，再从本工作副本运行，显式指定网页目录：

```powershell
$env:DND_CARD_WEB_ROOT='C:/Users/admin/Documents/Codex/2026-10-17/new-chat/embedded-web'
node tools/build-workbench-dev.mjs
node tools/workbench-performance-preview.mjs
```

测试入口为 `http://127.0.0.1:5353/`，只绑定本机，包含 200 张自行生成的角色卡。房间宿主使用生产控制器，边界使用 SDK 模拟器，网页来自上述显式目录的实际构建。数值保存与正文读取记录在 `.local-evidence/performance-preview/browser-metrics.json`，不连接公网房间，不读取用户卡库。

真实 SDK 浏览器检查可用 `OWNER_SERVE_ONLY=1` 启动 `tools/workbench-owner-cold-sdk-selftest.mjs`，再通过受控浏览器打开对应地址。该模式本身不启动外部浏览器。
