# 2026-10-11 · 插件权限矩阵、信任边界与本次修补

配套网站文档：DND-card-web `docs/PERMISSIONS-20261011.md`（云端 API 与网站端规则）。

## 信任边界：谁真的在把关

- **枭熊房间、场景、棋子元数据任何成员都能写**。插件自己也从玩家的宿主写它们（`src/workbench/background.ts`、`panel-rpc.ts`、`qq-page.ts`）。因此原生卡的 `locked`/`visibility`、目录 `owner_ids`、QQ 登记表 `com.obr-suite/qq-cards`、`deleted-cards`、目录 `url` 都只能约束诚实的客户端，不是安全边界。
- **服务端真正判定的只有两处**：dnd.center 云端 API（卡主、编辑者、锁定、修订号、凭据、CSRF），以及 obr.dnd.center 角色 API。后者没有鉴权，知道房间与卡 id 即可读写删，代码不在任何仓库里，本次没有改动。
- **中继**（`server/workbench-relay`）只校验宿主/客户端密钥、注册房间与共享文档范围，不判定玩家身份。
- **原生卡的所有权 = 枭熊 Set Owner**：绑定了该卡的棋子的 `createdUserId`。目录里的 `owner_ids` 不作数（`native-owner.ts`）。
- **枭熊自身的 `CHARACTER_UPDATE` / `CHARACTER_OWNER_ONLY` 权限**决定玩家能否真的写棋子。插件没有读取它们，状态追踪、血条、先攻等直接写棋子的操作由平台兜底拒绝。

## 原生卡（上传到 obr.dnd.center 的卡）

| 操作 | DM | 棋子所属玩家 | 其他玩家 |
| --- | --- | --- | --- |
| 在工作台/面板里看到 | 是 | 是 | `visibility` 为 public 且未锁定 |
| 棋子信息弹窗 | 是 | 是 | 另需血条未锁（`canReadNativePopup`） |
| 编辑、保存、资源 | 是 | 是，锁定的资源除外 | 否 |
| 锁定 / 解锁 | 是，同时设置 visibility | 是，只改 `locked`，不改 visibility；DM 的 `dm` 隐藏不会被解锁撤销（本次） | 否 |
| 删除 | 是 | 仅当没有他人棋子绑定 | 否 |
| 上传为云端卡 | 是 | 仅当没有他人棋子绑定（本次，与删除同规则） | 否 |
| 绑定 / 解绑棋子 | 是 | 否 | 否 |
| 创建 / 上传 | 任何人；创建者不自动拥有，需 DM 绑定其所属棋子 |

## 云端卡（QQ 卡库加载到房间的卡）

| 操作 | 卡主 | 指定编辑者 | 房间成员（持房间凭据） | DM 身份 |
| --- | --- | --- | --- | --- |
| 读 | 是 | 是 | 是，锁定与否都可读 | 与成员相同 |
| 编辑并写回原卡 | 是 | 是 | 仅解锁期间 | 不额外授予 |
| 锁定 / 解锁、授权、移出房间 | 是 | 否 | 否 | 否 |
| 删除云端原卡 | 仅在网站卡库；配对的插件令牌不能删（本次，服务端 `plugin_scope`） | 否 | 否 | 否 |

服务端判定为准。宿主在首次 GET 前用登记表的 `qqOwner`/`qqEditors`/`locked` 预判显示，GET 后以服务端返回的 `owner`/`editor`/`write` 覆盖。锁定只限制写入，不限制阅读；重新加载只更换凭据，不改锁定状态。

## 怪物、棋子与房间资料

- 怪物（带怪物组件的棋子）：DM 或创建者可写；`allowPlayerMonsters` 开启且未 workbench 锁定时其他人可读。
- 资源：锁定的资源仅 DM 可改、仅 DM 可切换锁。工作台一直如此；稳定版资源编辑器本次改为同样规则（`resourceTracker/storage.ts`）。
- 血条锁（`statsLock`）：仅 DM。
- 状态：能读到的卡可以被添加状态（grant），写回仍需写权限或"可接收"。
- 共享规则（`shared.ts`）与笔记：仅 DM。公共仓库：DM 或未锁定。

## 中继

- 宿主与客户端各持一把密钥，宿主注册时绑定房间；工作台链接里带客户端密钥，复制链接即获得该玩家的全部工作台权限。
- `sharedDocument`：规则、场景索引与库存账本限定为注册房间；怪物覆盖文档保留来源房间（本次）。
- `deleteCard` / `saveCard` / `createCard`：仅宿主角色；房间参数不限定，因为旧卡保留原上传房间的地址。

## 本次修补（dev 线）

1. 原生卡锁：所属玩家锁/解锁只改 `locked`，不再把 DM 的隐藏改成公开。
2. `cloudUpload` 与删除同规则：有他人棋子绑定的卡只有 DM 能上传成云端卡。
3. QQ 面板 `account.request`：不再允许直接 `PUT room-cards/<id>` 绕过宿主的锁定资源、AC 与修订规则，只放行 `/lock` 与 DELETE。
4. 怪物覆盖文档键必须是 `monster_<房间>_<棋子>`，棋子元数据不能把它指向库存账本或规则文档；读取同样校验。
5. 中继共享文档按注册房间限定（自检 19 项含三项范围检查）。
6. 稳定版资源编辑器遵守资源锁。
7. 配对校验码：插件登录时显示 6 位校验码，网站授权页显示同一校验码并要求核对（防止被诱导为别人的连接授权）。
8. 文档修正：重新加载云端卡只换凭据、保留锁定状态。

## 已核对、保持不变

- 云端卡在工作台对所有成员可见（含锁定卡）：与服务端"锁定只限写"一致。
- 信息弹窗额外要求血条未锁：这是"数值可见性"规则，与"卡可读"规则并存。
- 目录 `url` 可指向同源的其他文档：旧卡迁移需要，`tools/workbench-read-recovery-selftest.mjs` 固定该行为。
- 创建者不自动拥有所创建的卡：所有权只来自 Set Owner。
- 状态追踪、血条增删、先攻等直接写棋子的入口没有插件侧角色检查：由枭熊权限决定。
