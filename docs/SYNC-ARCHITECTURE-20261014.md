# 同步架构目标与首轮实施 · 2026-10-14

状态：开发候选。部署和真实多人验收均未完成。

开发基线：Suite dev `1da07532fae10b2f7ad6cc75979b23cb0ace19fa`（轻量 2D 292）；配套 Web `233a0638e85bd8ff8856022736340e11998dd18d`。已接续远端 `3fbea9148b753ce662831032458302e45f9c6e54` 的中继回执/入口修复。不修改另一会话的骰子逻辑，不发布稳定插件或后端。

## 数据归属

- A：角色/怪物业务数值、完整角色资料与库存账本的服务器裁决者。
- B：枭熊棋子。位置等原生场景字段继续由枭熊管理；业务数值字段作为 A 的公开运行投影。
- C：网页缓存、显示状态和独立编辑草稿。接收同步不会自动产生新写入。
- 图片、规则正文独立缓存，通过稳定 ID、地址和内容版本引用。
- 每类数据只有一个裁决规则。副本可以存在，禁止多路独立结算。
- 私密内容不进入公开 metadata/广播；推送、补发、快照均按当前权限过滤。

目标流程：业务命令 → A 事务保存状态/操作结果/待发送事件 → 插件接收授权差量 → 负责端写 B → 各端应用本地视图 → 发起端报告完成。完整资料与运行数值分别计版本；首次读取、版本缺口及恢复时才读快照。

## 不可退让的需求

1. 同一操作 ID 只能结算一次；网络重试查询结果，不重复扣除。
2. 旧版本不能覆盖已确认的新版本；增量缺口通过快照或事件补齐。
3. 本机必要 metadata 与数值显示尚未更新时，不报告场景完成。
4. A 已保存而场景失败时，报告已保存、场景待同步，只重试投影。
5. 普通操作不等待全员准备/回执；不同角色的结算不应被全局队列串联。
6. 原生 B 编辑作为显式兼容入口；只由负责端提交，投影不回环。
7. 接收常规扣血/资源事件不新增整卡下载，不因无关移动重读所有角色。
8. 保存响应丢失、负责端退出、后台挂起、场景切换均能恢复且不重复执行。
9. 无在线插件时 A 仍可保存，B 留待上线补齐；旧 B 不能覆盖较新的 A。
10. 投骰属于独立即时事件；2D 不加载物理 Worker/WASM，不等待全房间。

目标后端先采用单体服务、支持事务的数据库、小型事件表；HTTP 命令 + 带游标 SSE，必要时回退长轮询。服务器操作结果和待发送事件必须与业务修改一起提交。广播仅承载小型即时事件，不能代替持久补漏。

## 首轮已实施

- 血条保留 `items.onChange` 提供的完整事件快照。普通更新不再附带全场景棋子、网格 DPI、场景 metadata 三次读取。
- 场景切换清除缓存；订阅先于初始读取，迟到的初始结果不覆盖新事件。网格和场景设置在场景边界读取。
- 插件的共享观察缓存可把补偿读取结果交给血条，避免漏掉一次 SDK 事件后显示一直落后。
- 绑定角色的 `setTokens` 观察本机 metadata 应用及血条本地 SDK 写入完成，再正常返回。最多等待 2 秒；超时走已有 `COMMITTED_PROJECTION_PENDING`，不会重放业务保存。
- metadata 事件可先于 SDK RPC 回执到达。观察到应用结果即可释放该卡投影；迟到的回执不继续占用后续投影。
- 值相同但版本过旧、新 stamp 配旧值、stamp 后的原生编辑，均不能错误确认。
- 血条可跳过中间状态直接显示更高的已确认版本，旧操作也能完成，不因缺少中间画面永久等待。
- `projectionPending` 同时考虑 metadata 和本地血条，血条回执仅刷新选中卡状态。
- 网页复用原有“资料已保存 · 棋子显示待同步”状态，不修改网页规则消费者或覆盖报告。

本地回执表示血条所需的本地 SDK 写入已完成；它不是 GPU 像素测量，也不是所有远端已显示的证明。关闭/未启用的血条、无对应棋子的卡不会产生无意义的显示等待。

## 初版性能验收目标

条件：4 人及 8 人，约 200 个棋子，相关页面位于前台，服务器 RTT ≤100ms，常用资源已加载。以下是目标，不是实测成绩。

| 指标 | P95 目标 |
| --- | --- |
| 点击反馈 | ≤50ms |
| 普通 2D 本地首帧 | ≤100ms |
| 数值修改至本机正式显示完成 | ≤500ms |
| 数值修改至远端正式显示完成 | ≤800ms |
| 收到 metadata 后本端数值显示更新 | ≤50ms |
| 常规运行数值事件 | 目标 ≤2KB，不带图片或规则正文 |

记录操作 ID、排队/保存/metadata/绘制各阶段、消息大小、整卡读取次数和 metadata 写入次数。跨端计时校准时钟，回执 RTT 不直接算作单向延迟。
