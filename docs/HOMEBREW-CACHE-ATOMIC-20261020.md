# 资料更新失败时保留旧缓存

## 已复现的问题

在隔离浏览器中运行原 `dev` 的真实资料缓存模块，分别更新 JSON、Markdown 和 URL 订阅。原实现先删除旧文件，再写入新文件；写入失败会让旧资料从当前页面和重开后的搜索中消失。索引写入失败还可能被吞掉，接口仍报告成功。并行窗口更新、失败订阅回执及删除期间迟到的刷新，也可能覆盖其他资料或重新留下孤立文件。

测试使用原创资料、真实 IndexedDB 和主动注入的存储异常，不实际填满磁盘，不操作玩家账号、枭熊房间或人物文件。原模块的十三个反例全部失败，日志保留在私有工作记录中。

## 修正

资料文件、文件索引和订阅索引在同一个 IndexedDB 事务中提交。事务读取当前持久索引，成功后才更新内存；失败则整组回退，保留旧文件及其记录。手工同名重导入继续覆盖旧同类文件；URL 更新继续沿用原文件 ID，失败后可以重试。并行更新保留其他文件，迟到的刷新不得恢复已经移除的订阅。

保留原缓存格式、数据库名称和对象仓库，没有清空缓存、迁移玩家数据或修改来源内容。默认来源开关、权限和规则执行保持原边界。

## 验证和限制

- 十六项实际浏览器检查通过，核对当前内存、原生 IndexedDB 文件键和重开后的结果；包含文件／索引／订阅写入失败、事务中止、网络／解析／不支持输入、并行窗口、迟到刷新、重试及无重复更新。
- 十三个旧模块失败用例在候选中通过，另三项刷新输入验证检查通过；没有删断言、忽略异常或延长时限。
- 插件类型检查通过。完整插件构建、既有回归和最终提交的 CI 仍须单独通过。
- 本模块属于 Suite 资料缓存，这组检查不代替规则自动化回放或真实房间验收。Web／Data 未修改，也未新增规则完成数。
- 职业／子职业及其特性的导入支持另列第 33 项，本候选尚未处理；不能据此宣称“贤者 3 级特性”反馈已解决。

候选独立保存，未合并或发布。代码回滚可使用原缓存格式，不需要删除或回盖数据。
