# 角色卡列表读取与双语入口

## 已复现的问题

在提交 `44a53a4` 的真实列表页、Edge 浏览器及隔离的 SDK 消息边界中，复现了旧读取覆盖新权限：玩家打开 owners 卡后，较新的 dm 撤权结果先返回，旧授权读取随后返回，卡片重新出现在列表并可再次显示 iframe 元素。子 iframe 使用本地占位，因此这项证据确认列表发现权限回滚，不等同于真实全屏角色卡内部正文的联合验收。

同组复现还包括：初次角色读取期间错过降权事件、初次列表读取期间漏接更新、切换空场景仍保留原列表、owners 可见性按钮提示改为公开而实际改为 dm。恢复英文下载按钮后的初版布局还将关闭键挤出固定宽度侧栏；已在本批修正。

## 修正

- 在首次读取前订阅角色、场景就绪和元数据变化。角色事件使旧身份读取失效；元数据事件同步应用完整快照，并使较早的读取失效。删除整个卡片列表键也会清空列表。这里没有把排队的旧事件快照复用到之后的异步操作中。
- 读取结果同时检查请求与场景代次、页面存活。撤权或删除时卸载对应 iframe，场景关闭时清空该场景列表和所有卡片 iframe。仍可浏览的卡片按原方式缓存，切回时复用。
- 初次身份与卡片数据分别就绪后恢复选卡，未完成时显示读取状态。读取失败提供同页重试；初次就绪查询失败保持未知状态，避免误判成永久无场景。先到的元数据快照使迟到的就绪查询失效，不会卸载再重建已显示卡片。
- 关闭页面时注销这批管理的语言、角色、场景和广播订阅，并使未完成读取失效。
- 可见范围提示按本机语言显示，owners 使用“DM 和指定玩家”，不推算不可靠的人数。按钮提示跟随实际下一步：owners/public → dm，dm → public。
- 补齐两版下载按钮原先缺失的词条，英文模式也能找到当前中文模板；设置页和列表页都明确文件内容是中文，下载保留原文件名。完整英文模板尚未接入下载。侧栏标题与关闭键放在首行，两下载按钮在下一行换行；上传遮罩与页面标题也补齐英文。

## 验证和后续

基线与初版布局各有 10 个浏览器场景及保存的源码散列。最终读取回归、实际截图和构建结果集中记录在 `docs/IMPLEMENTATION_PROGRESS_20260908.md`；本机原始证据位于 `_audit/2026-09-08/cc-panel-review`。另一个代理独立检查了就绪查询失败和先到元数据两条新增路径。

这批验证使用实际列表 DOM、同页事件和 iframe 元素；角色卡子页面及 Owlbear 宿主由边界替身提供。真实房间、实际完整子卡联动和上传服务仍待验收。列表显示权限不是服务器文件访问控制；上传、覆盖和删除的并发写入仍需后续独立核对。

后续第十三批已完成这组写路径的独立复现与修正，见 [写入研究记录](character-card-panel-writing-20260908.md)。就绪读取现在区分：同场景迟到的成功可以确认写入可用且保留已显示 iframe，失败提供重试；旧场景结果仍失效。本文上述读取证据对应第十二批，不将新增写入行为倒填为原先已验证。
