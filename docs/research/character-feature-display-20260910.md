# 角色卡特性显示与直接阅读

悬浮卡缺少战斗风格和特殊能力，原来的名字按钮也不能阅读角色卡中已经填写的说明。现在补齐这两组，有说明的特性、专长和法术点击名称直接展开，长文字保持换行并在现有面板中滚动。需要查资料时可点搜索；没有本地说明的条目仍直接搜索。

两组新标题提供中英文。正文采用角色卡明确提供的 `description_en`/`description_zh`，否则保留作者原文，不自动篡改自定义规则。切换语言保持已展开的条目，不重新请求卡片、不写入角色或地图数据。键盘 Enter/Space 同样可操作；撤销查看权限或切换角色会移除原说明。

## 本地验证

- 定向浏览器检查先运行已提交旧代码，确认战斗风格/特殊能力均缺失且没有正文阅读区，再检查新代码。两版原生保存后上传所得 JSON 作为固定诊断样本，逐字核对特殊能力说明。
- 24 项检查涵盖五类分组、重复法术、完整中英文文本与回退、展开状态、搜索行为、标记转义、长无空格内容在 320px 面板换行、全文末尾可达、键盘操作、无额外读写与权限清理。320px 中英文实际截图已查看。
- 30 项原有 DOM 检查及 45 项整合检查通过；后者使用实际悬浮页、HP/资源编辑器和状态更新实现。Owlbear SDK、骰子及布局边界受控，不等于真实房间验收。
- 首轮新测试把所有面板同步消息都算作搜索，因此停在“打开说明不搜索”。修正为只检查 `com.obr-suite/search-query` 后通过，并按现有模拟 SDK 的 `data` 字段核对实际搜索词。初轮构建保留，不改记为通过。

工程样本为 `tools/fixtures/cc-imported-2014.json` 与 `cc-imported-2024.json`，来自[上一批原生保存与上传诊断](xlsx-dynamic-save-20260910.md)。它们只含测试填写的数据，不是完整英文卡。浏览器入口为 `tools/cc-info-entries-browser.mjs`，`CC_ENTRIES_OUT` 指定新的输出目录。
