# AV1 工程副本的包级保真

[`export_package.py`](../../tools/xlsx-localization/export_package.py) 将已审核的 AV1 公式计划实际装入两版工程副本。它从原始 ZIP 开始，用有限 XML 字节替换新增隐藏 Export 页；不使用工作簿库整本保存，不修改原件或公开下载。它没有执行英文页名/正文迁移，也保留原 AS41 导出语义，不能称为英文角色卡成品。

## 生成与复跑

```text
python -X utf8 tools/xlsx-localization/export_package.py
python -X utf8 tools/xlsx-localization/export_package_selftest.py
```

默认每次在仓库相邻 `_audit/xlsx-export-package` 下创建独立 UTC 时间戳目录，最后输出两份文件的绝对路径和散列。指定 `--output-dir` 也必须位于该审核目录；已有文件、原件和公开下载均不覆盖。测试自行准备新的输入快照及输出，不依赖上一次生成，也不在仓库内添加二进制文件。

## 实际变化

| 项目 | 2014 | 2024 |
| --- | ---: | ---: |
| 原有工作表 / 隐藏页 | 17 / 7 | 18 / 8 |
| 原有单元格 | 63,115 | 75,138 |
| 原有公式格 | 5,538 | 7,160 |
| 原有命名范围 | 329 | 3 |
| 新隐藏页辅助公式格 | 925 | 1,028 |
| AV1 新公式 UTF-16 单位，含等号 | 265 | 267 |
| 新公式最长 UTF-16 单位 | 2,327 | 2,327 |
| 新造公式缓存 | 0 | 0 |

两份当前原件仅有五个旧部件改变：实际主表中 AV1 的 `<f>`；workbook 的新增 sheet 与三个重算标志；workbook 关系；内容类型；docProps/app.xml 中的工作表数量和标题列表。另新增一个隐藏 worksheet 部件。其余每个原单元格、样式、原共享字符串、验证、名称、隐藏状态、图像和外链部件保持；不访问外链目标。ZIP 内解压后的部件字节及已有 ZipInfo 元数据核对保真，压缩流和中央目录位置会重建，文件变小不能证明打开更快。

旧 AV1 的缓存字符串与原公式模型、新计划模型逐字符相等，才保留其原 `<v>` 字节；这仍是旧缓存，不是新计算结果。辅助格只有公式、没有 `<v>`。工作簿设置 fullCalcOnLoad、calcOnSave，并把 calcCompleted 标为未完成；保留原来的其它计算偏好，不永久开启 forceFullCalc。新增约千个辅助公式的实际重算成本仍需测量。

## 输入与证据边界

计划由散列锁定的原件和已审核生成器产生。生成器先规范 Git 的 LF/CRLF 换行，再对即将编译的同一份字节核对散列。写入前核对原件、快照和计划未变，验证所有声明格、来源范围、函数、预算及全图拓扑，再与新生成计划逐字段对照；写入前后都重查。重复或缺失 helper、不可达循环、外部引用、篡改和超预算不会被静默修补。

两真原件没有 calcChain。合成派生包验证了登记链的部件、关系、内容类型同时移除。独立审阅又发现“已有合法登记链并带另一个无关系的 calcChain.xml”在原型中被接受；项目工具已明确拒绝该命名组合并增加回归。这是边界声明的收紧，不表示现有两份副本损坏，也不把任何任意名字的 XML 都猜作正式计算链。

原型作者的 104 项检查、另一代理独立的 40 组基线与 12 次变异拒绝分别保留，不能合并成原生兼容证据。独立工具使用自己的 XML 字节定位和公式解析/求值，直接读取包内实际公式、依赖及缓存。仓库工具加入自包含准备、换行兼容和命名链组合拒绝后，根的 106 项检查通过；最终来源散列和 CLI 检查在进度记录及本机审计目录中汇总。原型冻结在 `_audit/2026-09-08/xlsx-export-formula/packaged-prototype`，不以修改历史副本覆盖问题记录。

Excel/WPS 原生打开、完整重算、保存后缓存、修复提示、渲染与性能尚未验证。还需通过实际可编辑字段触发 JSON 转义和长度边界，比较新增错误与原件已有错误，并走真实角色卡上传。英文正文、页名及查找键、下拉与相关公式、AS40 盾牌字段迁移仍继续进行；工程副本不会提前接入英文下载入口。
