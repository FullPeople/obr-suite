# 资源工具的原生入口与窗口归属

旧入口在每次切语言时先注销工具再注册。独立基线还复现了旧注册回执删除新工具、旧总览打开回执关闭新窗口，以及注册/注销失败被吞掉后模块状态与宿主资源不一致。基线语言检查中的窗口和草稿本身没有丢失，不能把“注销重建”直接描述为已复现草稿丢失。

工具保持原 ID，同一会话只重新提交描述，不注销、激活或切换原生模式；相同已确认语言不产生 SDK 调用。GM 图标过滤和会话守卫阻止失效回调重新打开总览。首次角色、连接、场景读取及注册失败交给已有模块管理器处理。

注册与清理串行，注销成功才释放归属，重启先清理仍属于旧会话的 ID。总览使用独立打开/关闭队列，旧打开必须完成并清理后，新窗口才打开；已派发宿主调用仍无法撤回。关闭失败保留窗口、草稿与原有本机打开标志。打开已经应用却丢失回执、随后清理又失败时，下一次打开先重试清理，不覆盖那个尚未确认的窗口。

独立审阅修正两处额外问题：发出语言更新前撤销旧标签缓存，使“宿主已应用但回执失败”后的语言回切可恢复；每次启动单独记录是否已收到角色事件，使与旧值相同的新事件也能压过初始旧回复。没有把普通姓名/颜色事件当作角色变更，因此正在编辑的会话与总览不被这些事件作废。只有实际角色变化才更新原有编辑会话版本。

资源数值权限、存储、拖动、表达式、资源编辑消息和后台提示协议未扩展；独立 TypeScript AST 比较确认八个原有读写/编辑/提示函数的正文除换行外不变。总览继续使用既有页面关闭标记，没有新增房间消息或资源数据写入。

验证入口：

```text
node tools/resource-native-entry-selftest.mjs --verify-mutations
node tools/resource-ui-selftest.mjs --mutations
```

原生专项使用实际模块、已安装 SDK API 与 ModuleLifecycle，测试端点控制宿主延迟和失败。旧变异器曾把多行锚点缺失导致的构建错误误计为成功：旧 55/5 应为 55/4，根最初扩展的 63/7 应为 63/6。现在统一换行、要求唯一锚点与构建成功标识，只接受指定运行期断言并保留子进程原始日志；严格重跑 63 项和 7 个有效变异通过。另一代理独立验证六个场景、11 个验收检查组和三个针对性变异，包括同角色事件保留实际编辑会话守卫。

旧输出和更正结果分开保留于本机 `_audit/2026-09-08/resource-native-entry`。最终固定树与构建结果在进度记录中汇总。受控 API 与浏览器检查不是实际 Owlbear 房间验收，不证明真实工具栏显示、所有原生关闭顺序或多人行为均已完成。
