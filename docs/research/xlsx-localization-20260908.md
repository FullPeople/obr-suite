## 不能只换页签、表头的原因

1. **显示值也是计算用的值。** 两版 `主要` 的数据验证都包含 `"是,否"`；同表公式又比较 `"是"`。技能/属性/职业和装备名称也是 VLOOKUP、MATCH、COUNTIF 等的查找键。翻译某一处必须同步核对引用和匹配关系，不能全局字符串替换。公式字符串、条件格式字符串、验证提示和批注已单独列出。
2. **页签参与布局识别。** 初始只读调查参考的相邻服务 `U:\枭熊插件\character-cards-server\parser.py:623`、`:642`、`:1472` 依赖 `起源`、`背景`、`主要`；`:1469` 以 `data_only=True` 读取公式缓存。该路径在 obr-suite Git 树外，以上行号是调查基线，本次标签审核没有重验服务的最新实现或部署状态。模板制作时仍需按当时权威服务的实际布局/别名契约验收，并保留 2014/2024 的布局差异。
3. **前端表头识别已有独立改进，仍需完整联测。** 初始调查发现固定 `sheet2.xml` 和中文 `盾牌` 依赖；本批复读 [xlsx-shield-state.ts](../../src/modules/characterCards/xlsx-shield-state.ts) 确认主代理已改为通过 workbook relationships 定位 `主要` / `Main`，接受 `盾牌` / `Shield`、`AC` / `Armor Class`、`着装` / `Equipped`，并校验导出标记。仍使用已知布局的 `AL39/AQ39/AS39` 与 `AQ40/AS40`；支持英文表头不等于全部公式、下拉或 XLSX 重算/上传已验收。本批未改此前端代码。
4. **字体名、定义名称、作者署名、图片不能混为正文。** 不应把中文字体家族名机械翻译为一个不存在的字体，也不能删去署名来达到“无中文”。清单记录文字和字体属性以供逐项判定。工作簿仍有媒体图片；本批未对图片 OCR/视觉验收，因此 XML 文字清零也不能单独证明全英文。

## AV1 与既有公式问题

| 原件 | `主要!AV1` 公式字符数（不含显示用等号） | 缓存 JSON | schema | ruleset |
|---|---:|---|---|---|
| 2014 | 8,013 | 可解析，1,897 字符 | `obr-suite-card/v1` | `5E2014` |
| 2024 | 8,663 | 可解析，1,848 字符 | `obr-suite-card/v1` | `5E2024` |

Microsoft 文档列出的公式内容长度上限为 8,192 字符，2024 原卡已超过该上限；2014 也接近上限，英文页签引用变长可能进一步增加长度。[Excel 规格与限制](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits)。这是原件的静态兼容风险，**不是已经观察到 Excel 崩溃，也不是 WPS 行为的结论**。不能用现有 `<v>` 缓存能解析来宣称重新计算已通过。

两版 AV1 直接将 `E3`、`E4`、背景名称等文本拼接到 JSON 引号之间，均无 `SUBSTITUTE` 转义。包含双引号、反斜杠或换行的自定义名字/正文需要专门验证 JSON 转义。下一阶段应在保留 schema、ruleset、键名和数值含义的前提下处理，不宜继续加长一个接近/超过上限的公式。本批没有改动导出公式或增加简化版角色卡。

原始缓存还包括：2014 `种族` 78 个 `#N/A`；2024 `种族` 84 个 `#N/A` 与 `装备!AO59` 的 `#REF!`。2014 有 285 个定义名称的表达式含 `#REF!`，另有 3 个外部工作簿关系；2024 有 1 个旧外部工作簿关系。保留这些证据，不擅自删名称、断链接或把全表扫描到的错误都归因为本批翻译。大量公式缓存为空，其中包含有意返回空串的公式；空缓存数量不能当作损坏数量。

## 可执行的下一步与核验

在规范仓库根目录运行（以下 Python 可替换为相同版本的已安装 Python）：

```powershell
$xlsxPython = 'C:\Users\admin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $xlsxPython -X utf8 tools/xlsx-localization/prepare.py --verify
& $xlsxPython -X utf8 tools/xlsx-localization/selftest.py
& $xlsxPython -X utf8 tools/xlsx-localization/candidate_selftest.py
```

新检出先不带 `--verify` 运行一次，生成未纳入 Git 的大文本/结构清单。`--verify` 仅读取原卡，重建并逐字节比较清单，不会覆盖原卡或清单。**不要直接编辑生成的 catalog**：基础审核在 [reviewed.jsonl](../../tools/xlsx-localization/reviewed.jsonl)，后续完整正文由 `batch.py` 合并到 `reviews/*.jsonl`。最低每行契约为：

```json
{"id":"catalog 中的精确 ID","version":"2014","source_sha256":"prepare.digest(source) 的值","target":"经完整上下文审核的英文","reviewed_by":"审核者","note":"版本、来源与术语核对说明","dependency_review":"pending","application_approved":false}
```

合并会拒绝未知/重复 ID、版本不一致、原文散列不一致、缺少审核说明或仍含中文的译文，并拒绝把语义审核变成写入许可；提供的 source/kind/sheet/context 还必须和原记录吻合。正文不因名称相同而共享译文。页签、公式文字、下拉值和主卡字段的依赖还未验收，不能仅按 target 填充。后续可按版本/页/来源书分批组织翻译，每批保留缺失数量，最后再制作完整英文副本。

[verify_candidate.py](../../tools/xlsx-localization/verify_candidate.py) 可读取未来的英文副本，检查页签/单元格位置、公式位置和类型、合并区域、下拉作用范围、外部链接、对象部件以及 AV1 键/类型/ruleset/缓存/公式长度。经明确审批的公式或布局变化必须绑定具体 before/after 散列；不能使用“允许这个单元格任意改动”的宽松许可。`--require-english` 会检查包含隐藏资料及长文本的中文残留；必要的机器标识/字体/署名豁免需逐条列明。脚本不会自动施加任何翻译：

```powershell

```
