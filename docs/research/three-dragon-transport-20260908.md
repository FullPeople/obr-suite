# 三龙牌多人传输与恢复

状态：规则、界面及多人控制器仍在并行实施；本页区分已经落盘验证的基础模块和待完成的接线。不能据此宣布多人牌桌完成。

## 已实现的基础模块

- `src/modules/threeDragonAnte/protocol.ts`：界面与后台的 LOCAL 消息契约。面板发直接 `TableCommand`，后台返回 `TableView`。关闭面板只关闭本机显示；加入、离席、开局和新局是不同操作。每个玩家都可建桌，建桌者负责发牌和结算，不要求 GM 身份。
- `private-channel.ts`：使用浏览器原生 ECDH P-256、HKDF SHA-256 和 AES-GCM。私钥不可导出；公开密钥指纹必须与导入的键一致。派生密钥绑定 roomId、tableId、主持人随机握手 sessionId 及双方实际连接/密钥身份；AES 附加数据还绑定消息编号、顺序与分片数量。未加密包没有手牌正文。
- 每个加密明文最多 64 KiB，按每片 10,000 个 base64 字符拆分，最多 9 片。接收方按实际 SDK 发送连接、收件人、牌桌和密钥身份验证，完整重组后才解密。保留 64 个序列的重排窗口并拒绝重复；最多 8 个不完整组和 8 个在途解密，15 秒未完整的组会在后续收包时清理。超量包不消费合法序列，发送端可重试。
- `wire.ts`：只发送静态卡片 ID，客户端从内置牌表还原。公共投影显式列出允许字段，即使输入 SeatView 也不携带手牌、秘密下注、私有候选、种子或牌堆顺序。私有投影完整保留所有合法候选，不截断选项。规则增加公开效果/大法师状态时，传输也保留这些信息。
- `store.ts`：完整主持人状态保存于本机 IndexedDB，按房间和牌桌隔离。比较 serial 和写入发生在同一个 readwrite 事务中，旧标签页不能覆盖较新状态；以事务完成作为成功依据。存档不放进 OBR 元数据，也不由控制 iframe 持有。

Owlbear 的公开广播只有 LOCAL/REMOTE/ALL，并且每条最多 16 KB，不能靠前端隐藏共享明文实现私密手牌。[Broadcast API](https://docs.owlbear.rodeo/extensions/apis/broadcast/) 原生密码原语用法依据 [deriveKey](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey) 与 [AES-GCM 参数](https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams)。没有自制加密算法或额外服务器。

## 已执行验证

- `node tools/runtime-selftest.mjs tools/three-dragon-private-selftest.entry.ts`：实际 Web Crypto 的 7 组回归。覆盖非收件人、错误实际发送者、内容/路由/密钥/序列/分片篡改、重复与并发重复、双向私密操作、中文长候选完整重组、房间/牌桌/握手隔离、重连密钥轮换、缺失 context 字段、解密工作量限制与重试、失效分片和 teardown。
- `node tools/three-dragon-storage-selftest.mjs`：实际 Edge IndexedDB，关闭页面再开仍恢复完整私有状态；两个存储实例同时写同一 serial 只有一个成功，失败后当前存档保持完整；不同房间/桌无交叉读取。公共/私有视图往返一致，公共字段白名单不包含手牌，ID 传输比完整卡片对象小。测试使用随机本地服务器端口和隔离浏览器上下文，不接触真实对局。
- 三份基础产品文件使用当前 TypeScript 严格模式检查通过。规则持续改动时需要重验完整构建及投影契约，不能用此处针对性检查替代整套构建。

## 控制器待完成的具体契约

1. `TABLE_ROOM_KEY` 仅保存 `TableSummary`：版本、桌 ID、主持人玩家/连接、阶段、座位和摘要版本。房间发现不持有任何完整牌局。读取 room metadata 必须用代次防旧读取覆盖；校验实际 SDK 房间成员/本机身份，不能信任载荷自称的角色或 seatId。
2. 所有访问者都与主持人握手；旁观者收到公共投影，入座玩家收到自己的私有投影。客户端 hello 使用唯一请求 ID；主持人产生全新随机 sessionId 并回显请求 ID。待确认的新链路和已经活跃的链路分开，只有新链路上成功解密的同步请求才替换旧链路。旧 hello/reply 不应造成已连接席位被踢掉或重复重设计数器。
3. 加密层允许有限乱序，应用层仍必须按 tableId、摘要 revision 和 game revision 拒绝旧快照。不能因为密文能解开就覆盖新手牌。客户端只能发送当前自己席位的合法 GameAction；主持人再次用实际发送连接对应的玩家映射 seatId，执行规则层的 revision、action ID 幂等及合法动作检查。
4. 所有主持人操作串行。先持久化规则结果，再发送成功回执与新视图；不能在保存失败后让玩家相信动作已完成。没有回执时保留原 action ID 重试，避免双扣金币/双出牌。metadata、IndexedDB 与广播没有跨系统原子事务，应保存待发布状态并重试发布，不重新发牌或静默丢弃已保存的动作。
5. 面板关闭/重开和普通场景切换不退桌，不销毁主持人规则实例。主持人离线暂停，回到原浏览器后从 IndexedDB 恢复并重新握手。相同玩家在没有存档的其他浏览器登录不应伪造恢复；显示 `recoveryMissing`。同账号多连接也不得同时主持，旧连接/旧异步回调失效。
6. 座位限制 2–6；创建者自动入座，玩家一键加入，开局前可退出。中途关窗保持座位；直接退桌不可导致手牌丢失，先限制到未开局。主持人确认「准备新局」后清除旧局、保留座位并回到大厅，允许玩家进退，再由主持人开始发牌；不能永久锁住首批座位。缺少恢复记录的新浏览器只可由原主持账号在旧连接离线后确认回大厅，不声称恢复了旧手牌。规则没有明确答案的 `adjudication` 状态必须呈现具体原因，不自动跳过。
7. 后台 LOCAL view/command/ready 的发送者必须是本机 SDK connectionId；加密/密钥协商只在有牌桌时启动。没有永久动画循环或逐帧持久化。SDK 失败、容量不足、握手超时均在同页可重试。

控制器、模块入口与界面现已实现；控制器验收见 `three-dragon-controller-20260908.md`。入口在首次打开或原主持账号恢复时才加载控制器，关闭窗口不销毁牌局。LOCAL 回放同样采用卡牌 ID 和有界分片，按窗口实例及页面 nonce 隔离，单发送队列只保留最新待发视图，不截断弃牌、记录和选择。

根复核新增 `three-dragon-local-view-selftest.entry.ts`：1198 个自然规则步骤中捕获完整视图最大 18162 字节，确认超过单条消息限制；压缩和分片后每包小于 12000 字节，原内容可完整还原。测试涵盖中文、表情、转义、倒序、旧视图、错误窗口、过期残片和重试。实际页面也接收超过一条消息的大视图，所有弃牌可在折叠区域查看，窗口重开后旧页面命令失效。

## 真实边界

主持人是可信发牌者，内存和自己的浏览器存档可以看到牌堆与各人手牌；本设计不声称抵御发牌者作弊、被篡改的插件源站或浏览器。其他玩家收到的房间网络数据应只有自己能解密的私有视图及公开摘要。存档保存在原浏览器，清理浏览器数据或丢失该设备会失去恢复来源，不能伪装成服务端保存。

最终仍需实际 Owlbear 的多人身份、消息上限、断线重连、多标签、各浏览器私密上下文/存储限制和完整实际对局验收。当前基础测试不证明这些宿主行为。
