# 角色卡 AV1 导出公式计划

2024 原卡的 AV1 公式有 8663 个字符，2014 为 8013 个；两版都把玩家文字直接拼入 JSON，引号和换行可使导出无法解析，反斜杠还可能被解释为转义而悄悄改变文字。本批新增 [公式计划生成器](../../tools/xlsx-localization/export_formula.py) 与 [原件回归工具](../../tools/xlsx-localization/export_formula_selftest.py)，尚未将计划写入可下载工作簿。

## 生成方式

读取真实原件的有限公式语法和已有缓存，将拼接、条件分支、数字判断及数组连接拆到新隐藏页。计划逐格声明公式和用途，最后的 AV1 保留原 schema/ruleset 字面量、原字段类型及输出地址。已有“网页导入”页对 AV1 的引用保持有效。每个动态字符串统一处理反斜杠、引号和控制字符，保留普通文字、CR/LF/CRLF、制表符、Unicode 和形似公式的文本，不使用 CLEAN 删字。

| 检查 | 2014 | 2024 |
| --- | ---: | ---: |
| 原 AV1 字符数，不含等号 | 8013 | 8663 |
| 新 AV1 UTF-16 单位，含等号 | 265 | 267 |
| 最长新公式 UTF-16 单位 | 2327 | 2327 |
| 新隐藏页公式格 | 925 | 1028 |
| 动态字符串来源格 | 209 | 229 |

长度格先计算完整输出预算，超限时输出明确错误，不截断 JSON，也不拿旧缓存替代。微软文档列出公式长度 8192 字符、单格文本 32767 字符，以及工作表 1048576 行、16384 列的限制；本工具采用保守的 UTF-16 长度计数。[Excel specifications and limits](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits)

不引入 LET/LAMBDA；沿用原 TEXTJOIN，并使用 IF、ISNUMBER、SUBSTITUTE、CHAR、LEN 和 SUM。原件模型和生成计划在所有原字段上比较，另外对真实动态字段、可选行、数字与空值、错误分支、32766/32767/32768 边界和转义膨胀进行验证。

## 独立审阅中的修正

独立复核发现三个输入检查缺口，现已修正：越界地址曾被模型当成空格而通过缓存比较；非法工作表名会进入公式；负数共享字符串索引会读取最后一条文字。现在统一核对 XFD/1048576 网格范围、工作表名称字符及长度、共享索引的非负整数和表内范围。

第一轮名称修正仅复用了正文检查，仍允许部分控制字符进入表名；后续将所有 U+0000..001F 限制在名称入口单独拒绝，正文里的合法换行/制表符仍保留。原件本身没有这些坏地址或坏索引，不能把损坏输入夹具写成原件已经损坏。

初版、第一轮根修正和最终修正的源码及证据分别保留在本机 `_audit/2026-09-08/xlsx-export-formula`。最终验证数量与所对应固定树在进度记录中汇总，不把历史版本测试当作新版本通过。

## 后续整合与明确限制

本工具只产生 JSON 公式计划，没有写 XLSX、修改原件或编造公式缓存。新页的部件、关系、隐藏状态、名称、依赖、calcChain 和重算设置还要通过包级保真验证；计划求值器不是不可信外部计划应用器，重复/缺失 helper 的篡改不能未经检查写入文件。

该阶段特意保留原 AV1 中 AS41 的旧盾牌来源，便于证明编译等价；修复为 AS40 属于另一项明确字段变更。中文/英文下拉、AC/重量公式、服务端、AV1 和缓存必须一同核对，不能把等价编译当成盾牌缺陷已经修复。

真实 Excel/WPS 重算、内部公式 token 大小、地区数字格式及 Unicode 计数差异尚未验证。完整控制字符转义方案也未证明兼容网页 Excel：微软说明网页版本仅支持 CHAR(9)、CHAR(10)、CHAR(13) 及 CHAR(32) 以上值。[CHAR function](https://support.microsoft.com/en-us/excel/char-function)

因此这些模型结果不能当作完整英文卡、真实导入或 Excel/WPS 运行验收；工作簿正文翻译、依赖迁移与排版继续进行。
