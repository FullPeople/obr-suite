# Portal image and editor verification

Room defaults use Owlbear's native single-image library picker. The selected image content is stored in room metadata for new portals; resetting a particular portal reads the current room default. Single and linked-pair creation use the same resolver and preserve existing trigger geometry. Availability uses browser media loading instead of a CORS-sensitive HEAD request, with a 1.5-second fallback deadline and a bounded positive/negative cache. Importing the background resolver creates no UI subscriptions.

Two actual preview regressions were reproduced and repaired in `default-image.ts`: a late initial room read could overwrite the just-saved preview, and a second unavailable selected image could lose fallback handling. Successful saves now invalidate the old preview read. Each selected preview has its own fallback handling; an unavailable bundled fallback stops retrying and shows a localized preview error. A pending native picker cannot write after role/identity invalidation, tab removal, page unload or a room change. A failed room write remains retryable on the same page. An already sent host write cannot be retracted; this does not provide cross-client compare-and-swap.

The actual portal creation/editor functions were also tested. The discovered add-ACK-after-scene-change defect was repaired by the agent owning `index.ts`. The editor now follows a current request and per-window instance, serializes native open/close, rejects old or remote close messages, and retains failed-close ownership. Layout repositioning follows the current requested editor rather than a stale physical window. Teardown reports a native close failure for retry. The editor page sends a local `{id, instance}` request; it no longer directly closes the shared native popover ID.

## Reproducible checks

- `node tools/portal-default-selftest.mjs --mutants`: 31 actual Edge scenarios and five compiling semantic mutants. Includes the installed SDK `AssetsApi` single-select/no-timeout picker encoding and actual `ImageBuilder`, default read/write/retry/fallback, cross-origin media without CORS headers, concurrent media resolution, actual appearance reset, actual single/pair creation, delayed add/viewport/role/native window replies, same-token new instances, local close identity, teardown failure and stale layout requests.
- Mutation results are accepted only when product/test file hashes match the baseline and only the named expected assertions fail. Each mutant has a fresh result directory, so old reports cannot supply evidence for a failed run.
- `node tools/portal-appearance-selftest.mjs --mutants`: 30 assertions and three compiling semantic mutants. The existing appearance suite was minimally adapted to the instance URL and local close protocol. Added checks cover a rejected close message, same-page retry, exact local `{id, instance}`, and absence of direct native close.
- `node tools/suite-wiring-ui-review.mjs`: 22 settings-tab views and 12 quick-bar widths. Confirms GM-only transition controls, no pointer/runtime card-table controls, a separate Three-Dragon Ante installation link, default enabled character/monster previews, Boss motion/inset preferences, music controls, library save retry, and scroll/hit accessibility.

Artifacts are outside the repository in `_audit/2026-09-09/portal-default-review`, `wiring-ui` and the appearance tool's printed temporary directory. The first baseline report preserves two product failures and an additional test expectation mismatch about SDK object properties with `undefined` values; that expectation was corrected, not counted as a product defect. The final default report records exact product/test hashes and all individual scenarios. Final English/Chinese default previews, the existing appearance editor, the narrow player bar and the independent card-table installation page were visually inspected.

All host endpoints are isolated substitutes: no real room writes or native library UI interactions were performed. The creation/editor test exposes actual private functions only in an isolated bundle and supplies initial lifecycle flags; it does not claim to exercise the entire portal tool-registration setup. Media cache tests verify image loading and timeout paths; they are not an all-video-codec certification. Real room windows, host RPC failures and GM/player devices remain acceptance boundaries. No deployment, staging, commit or push was performed by this subtask.
