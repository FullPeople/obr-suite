# 角色卡服务端盾牌输入修正

两份当前原卡都在“主要”页 AS40 输入是否装备盾牌，AS41 实际落在另一合并区域内。服务端沿用 AS41，且不认识“是”，因此真实原卡代理测试中 AS40=是/Yes 仍输出未装备。前端另有 AS40 修正路径，但不能依赖一次后续请求弥补原始导入错误。

本批在既有版本和工作表角色解析之后，要求现代布局、非明确 v1.0.0，并核对 AL39/AQ39/AS39 分别为“盾牌 / Shield”、“AC / Armor Class”、“着装 / Equipped”。只有这些证据同时满足时，才复制本次导入的主表布局，改为 AS40 并支持中文“是”。既有 Yes/No、旧符号、未知表头的 AS41 路径，以及无装备输入的旧版默认保持；共享布局常量不被修改。

这是接在上一批页名适配之后的独立增量补丁。输入必须是 `9791888eddaac50e771baaff0cc7e738ef1b5cb18b52a954344ccd2224512c34`，结果为 `ff02e712b37dd855e1af189969365c6049895d95c93733cb8126fe5610400766`；均为 UTF-8/LF。补丁 2700 字节，四处差异包含两处注释、已证明布局的覆盖和中文真值支持。[便携交付及复跑说明](../../tools/server-patches/shield-input-20260908/README.md)

真实原件通过只读视图测试中英主表、三表头组合、是/否/Yes/No、AS40/AS41 故意冲突、未知/缺失表头、旧版、零/空加值及重复导入；原件从未保存。完整解析只允许预期装备字段变化，已有 AC 和重量缓存及 AV1 overlay 均保留。独立验证器还重建两段旧 parser，逐字正反向应用两份补丁并执行原页名/资源检查。

没有增加零/空盾牌加值的布尔门槛。服务端仍可输出 equipped=true 且 ac_bonus=0/null；前端另有零/空门槛，本批未改变它。没有覆盖的非零 AC 缓存不重算；如果 AC 缺失且没有 AV1 覆盖，既有 fallback 会采用修正后的装备状态，因此正加值 2 可使 fallback 的 AC 增加 2。这是输入正确后的既有行为，未修改 fallback 代码。

原 AV1 的旧 AS41 引用、“是/否”下拉与 AC/重量公式、缓存一起迁移仍是后续工作。尚未执行真实 Excel/WPS 重算、上传服务或部署，也未完成全链路英文工作簿验收。最终检查数量与固定源码记录在进度文件，本机证据在 `_audit/2026-09-08/xlsx-server-shield`。
