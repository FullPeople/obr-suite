# 英文法术身份与查找公式

身份与查找工具从两份固定原卡生成逐行数据和公式改造方案。后续选择工具已接入明确的 C3 输入、英文及自定义法术下拉，实际工程副本也在相邻审核目录生成。完整英文角色卡下载仍未完成；整卡还须连接正文、显示规则、导出和上传。新增选择入口详见 [法术选择工程迁移](xlsx-spell-selection-20260909.md)。

## 实际冲突与显示

2024 原卡“法术大全”的 A73 和 A719 都是“圣言术”，N 列分别为 Holy Word 和 Divine Word，正文及环级不同。英文入口直接定位原行，保留两条完整数据。原中文输入维持原工作簿的第一次匹配；现有服务器的 A 键字典是最后一条覆盖，仍需另行迁移上传协议，不能声称两者已经一致。

N452 与 N646 都是 Sanctum of the Flock，实际 B 列分别为 3 和 5。显示为 `Sanctum of the Flock (Level 3)` 和 `Sanctum of the Flock (Level 5)`，原 A/N/M 均不更名，也不猜测哪一个才是官方名称。每条身份包含规则版本、固定原件散列及原行号；完整字段另有指纹，技术身份不显示在下拉标签中。

2014 共 522 条内置法术、50 个自定义槽；2024 共 809 条内置法术、3 个预留空行、50 个自定义槽。所有原字段与自定义公式引用均记录。2014 N337 是 `术Summon Elemental`：核对其全部 24 字段及完整正文后，仅为这个精确原件身份提供 `Summon Elemental` 显示修订，原 N、正文及字段散列保留。修订要求原名和完整字段的实际散列同时吻合，不对其他名称通用去字。可用英文标签现为 522 / 809。两版 Air Bubble 的 N 列尾空格仅在显示标签中裁去，原值不变。

`spell_identity.resolve_input` 是静态数据接口，英文输入会去除外侧空白；工作簿查找方案保持输入原空白，因此 `Air Bubble ` 不命中英文辅助表。两者不能逐输入宣称等价，上传对接时需要明确统一用户体验。Python casefold 也不代表 Excel 的全部语言排序规则。

身份工具的解析器验证内部字段与显示的一致性，不提供外来 JSON 的签名认证。查找工具直接从原件重新生成身份方案，并检查原件散列；不接收外部方案作为可信来源。

## 具体公式设计

两版均有 1,003 个直接查找法术资料的公式格：主卡 66、数据表 725、法术书 212。全表读取时，共享公式先从实际主格展开并核对从格范围，保留原始公式及属性。目标法术消费者本身没有共享从格：991 格无 f 属性、11 格只有 ca 属性、C3 是单格数组公式。分析器按真实函数参数和字符位置改造，不把引号中的 `VLOOKUP(...)` 当作函数。

规划的隐藏 `_OBRSpellMap` 工作表按原行记录身份、英文标签、原中文键、原行号和字段散列。G 列的 619 个辅助公式分别定位输入，同一输入和同一有效行区间共用结果。每个英文匹配返回原资料行号，消费者用 `INDEX` 读取原表和原结果列；未命中时执行逐字保留的原 `VLOOKUP`。外层拼接、错误处理和其他表达式保持原样。

英语标签按字面查找。`MATCH(...,0)` 的文本输入仍支持通配符，因此辅助公式转义输入中的 `~`、`*`、`?`，并排除空白及非文本输入，避免空标签匹配到预留行。没有引入 XLOOKUP、动态数组或整列扫描式的新定位公式。[Microsoft MATCH 文档](https://support.microsoft.com/en-us/excel/functions/match-function)

保留原查找表的起始行与宽度：对 A3 开始的有限表，原行号减去 2；对整列引用保持原行号。2014 法术书 O8 原先对 A:X 请求第 26 列，方案继续保留这个原错误，没有在翻译工作中静默改成另一列。[Microsoft INDEX 文档](https://support.microsoft.com/en-us/excel/functions/index-function)

两版各 1,002 个公式格得到完整候选表达式。原法术书 C3 使用 `INDIRECT(CELL("address"))`，依赖重新计算时的当前单元格，查找工具明确不改这个消费者。后续选择工具单独用可编辑的下拉输入替换 C3；其 11 个下游详情查找继续采用原查找方案。原生选择和重算尚未验收。

## 执行与验证边界

```text
python -B -X utf8 tools/xlsx-localization/spell_identity.py
python -B -X utf8 tools/xlsx-localization/spell_identity_selftest.py
python -B -X utf8 tools/xlsx-localization/spell_lookup_plan.py
python -B -X utf8 tools/xlsx-localization/spell_lookup_plan_selftest.py
```

身份输出位于相邻 `_audit/xlsx-spell-identity`，查找输出位于 `_audit/xlsx-spell-lookup`。每次创建独占的新目录，原件和历史产物不覆盖。新检出只需源码工具与两份 public 原件，不依赖某个历史审计脚本。

作者身份工具 39 项检查通过；独立审阅另有 24 组和 3 个编译有效的行为变异，独立核对全部 36,140 个资料行字段及 100 个表头字段。它还实际证明一致重算散列的外来 JSON 不受认证，明确保留该信任边界。

上述为第十九批来源的历史结果。N337 精确显示修订后，当前身份自测 43 项通过，查找自测仍为 43 项结构检查、有限标签用例增加为 16 个。独立增量另外通过 16 组和 3 个编译有效行为变异：2024 整份计划与固定旧源码输出完全相同，2014 整份计划仅行 337 的 display 和对应 diagnostic 改变。真实原件的 24 字段另独立读取核验；旧独立 24 组与作者 39 项没有重计为这次运行。

查找工具首轮 43 项源结构检查和 15 个有限标签行模型用例通过。独立审阅另有 66 项非空检查、40 个实际生成公式的有限执行场景、5 个编译有效语义变异和 6 次隔离 CLI。其初轮 70 条中有 4 条检查对空集合，已经排除；另从两原件 R13/R14 补验共享公式展开，各通过 1 项。没有把这两项说成共享公式写入验证。独立解释器检查实际 helper 与替换式的偏移、类型、原中文回退、同名正文和保留原列错误；它不是 Excel 引擎，也没有工作簿写入。

当前 CLI 只接受固定原件。内部规划函数仍不适用于任意外来公式：未来若允许同格混合动态与普通查找，应先判定整格或回滚辅助公式；通用化前还应补全所有行列上界检查。本批不扩大这些内部接口的契约。

选择工程副本已推进实际包关系、缓存清理、法术书紧凑列表和 C3 输入；这些包级结果不等于原生验收。整卡继续处理主卡下拉空白项、自定义槽改名后的选择与冲突、中文法术名条件格式、完整英文正文及富文本布局、XLSX 上传和 JSON 导出身份协议，以及实际 Excel/WPS 重算、保存、选择和上传。2024 自定义槽从 815 行开始，前面三格为空，不能把非空数量当作最后一行。
