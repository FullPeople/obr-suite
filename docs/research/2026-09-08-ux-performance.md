## 已有优化与不得重复踩的方向

已阅读共享目录 `docs/OPTIMIZATION_RUN.md`、`docs/DEV_VS_STABLE.md`，并结合此前三份跨模块计划/验收文档。前两份里的“线上 1.2.0 / 尚未部署”等时间状态已经过时，不能覆盖本次直接读取的 1.2.2/148。

- 已做过：拆分 i18n、部分能力按需引入、搜索索引小写预计算、墙与传送落点空间索引等。不要重复报成新发现。
- 旧优化明确拒绝无差别复用 `onChange` 数组：调度/防抖会令快照过期。后续优化只在事件版本、新鲜度及场景代次可证明正确时复用，不能为少一个 API 往返引入旧数据覆盖。
- 旧优化明确拒绝未经真实房间测量就把所有模块动态拆包：顺序 import 会串行下载；并发预取又影响启动架构。本报告建议先记录分阶段耗时，再做最小范围实验，保留既有注册顺序。
- 最新项目把两个频道的元数据命名空间合并，官方 Dynamic Fog 也存在重复派生墙/灯的共存风险；后续新插件必须明确自身职责与 ID，不可复制一套后台引擎。不能套用 D 盘旧“dev 命名空间必隔离”的规则。

以线上 HTML 直接声明的 script/modulepreload 为集合，去重累加下载内容：stable background 为 33 个 JS / 363491 bytes，dev 为 33 个 / 415479 bytes；stable settings 为 13 个 / 342445 bytes，dev 为 12 个 / 354353 bytes。按 gzip 本地压缩估算依次为 114498、133589、115056、119730 bytes。**这不是浏览器实际传输字节、完整进房总量或打开时间**；popover 后续加载和缓存命中另计。当前资产响应为 `max-age=3600`，HTML 为 `no-cache, must-revalidate`。可以在确认内容哈希部署策略后研究延长不可变资产缓存，但先测冷/热开差异。

### 界面简化的具体方向

1. 主界面只保留“我的角色、投骰、战斗、更多”这类当前任务入口，DM 才显示管理入口。选择 token 时在一个稳定信息面板里更新 HP、状态、资源和详情，不同时冒出几块相似浮窗。
2. 常用动作一键完成；自动弹窗、固定面板等个人偏好集中在该面板的小菜单，并记住选择。退出设置不用再次恢复布局。
3. 帮助说明、维护工具、反馈与赞助继续可达，但与日常控制分开。长教程默认折叠，不占据设置页首屏。
4. 正在读取、已缓存但在刷新、来源不可用应能区分；失败时在原位置重试，不要求刷新整间房间。

## Boss 史诗血条

### 已有与缺口

当前 `hpBar` 是与选择关联的 HP/临时 HP/AC 小面板，相关数据来自现有 bubbles 状态。其自动显示还排除了角色卡/怪物绑定 token（`src/modules/hpBar/index.ts:214-226`）。源码未发现面向全体玩家的 Boss 展示模式；设置里的 Boss 仅为普通血条用途举例（`src/settings.ts:2705`）。

### 建议第一版

- DM 右键 token → “显示为 Boss”，所有玩家屏幕顶部出现一个横向血条；再次点击隐藏。绑定现有 token HP，禁止另维护一份易失同步的生命值。
- 默认只公开名称与比例，精确数字、阶段分段、多个 Boss 排序放一个小设置框。变身前后遵循已有 HP 规则，不借本功能改变卡片数据契约。
- 伤害使用短暂拖尾，阶段转换一次轻量效果，战败一次收束；静止时不跑连续粒子或逐帧改场景数据。提供减少动态效果和隐藏演出的个人偏好。
- 单客户端本地绘制，共享的是 Boss 身份/显示配置与已有 HP 数据。采用持久状态恢复迟加入者；删除 token、隐藏 token、切场景和 DM 断线都有清楚的收起规则。
- 公开展示不能意外暴露未公开单位；是否主动揭示隐藏 Boss 必须由 DM 明确操作。显示比例并不等同于平台元数据保密，不能宣称本 UI 能隐藏 SDK 本来可读的数据。

## 玩家鼠标

源码没有找到玩家指针共享模块；现有 `cursor` 多为组件鼠标样式、拖拽预览和工具光标。

官方 [Tool API](https://docs.owlbear.rodeo/extensions/apis/tool/) 说明活动 ToolMode 接收移动事件；[Interaction API](https://docs.owlbear.rodeo/extensions/apis/interaction/) 提供指针高频互动示例，[PointerBuilder](https://docs.owlbear.rodeo/extensions/reference/builders/pointer/) 可创建指针。资料查询日期为 2026-09-08。

因此建议先做“按住快捷键/启用指示模式时显示姓名和彩色指针”的低成本原型，发送暂态坐标并在接收端平滑呈现。应优先验证互动 API，不逐帧写持久 scene metadata。公开 API 文档未提供任意宿主工具下全局鼠标监听接口：在玩家使用默认选择、画笔等工具时始终展示鼠标，不能仅凭上述 API 宣称可实现。不能用覆盖整个画布的捕获 iframe 阻断正常操作。

验收需要覆盖：默认拖 token、测距、画图、缩放、菜单、触屏、切出浏览器、断线与迟加入；移动停止或断线后指针自动消失，不留下永久场景对象。若只能在新工具里采集，向玩家清楚说明模式边界，不能伪装成“所有工具通用”。

- 第一版在现有套件“更多”提供“短休 / 长休 / 自定义转场”，点击后让目标玩家播放一次短效果；不自动恢复 HP/资源，避免把演出变成未约定的规则结算。
- 给每个传送门增加继承默认/关闭/眨眼/淡入淡出，旧门缺字段时沿用原行为。个人减少动态效果优先于房间演出设置。

- 第一版只允许 DM 向全体发起，玩家可预览自身效果；玩家面向全体触发应有明确房间权限，以免误触不断中断别人。
- 复用现有 modal/pointer-through 生命周期但独立跟踪每次效果；播放结束、关闭、取消和切场景都清理。静止效果页必须保持透明根背景。

## 性能与多人验收

这是建议量测方法和初始目标，不是已取得的成绩。

| 情境 | 记录与通过标准 |
| --- | --- |
| 冷进房间 / 缓存热进房间 | 记录宿主 ready→常用按钮可点击→第一屏内容可用三个时间；至少各 5 次并记录网络条件、设备、场景规模，不只报平均值。 |
| 打开/重开每个主面板 | 记录点击到有反馈、点击到可输入、内容到齐时间。初始设计目标：100ms 内显示反馈，缓存热开主面板 300ms 内可操作；真实基线后再确认目标。 |
| 1 个不可访问资料源 + 1 个正常源 | 正常源首屏照常可用，失败来源有状态与重试；不能无限 loading。 |
| 100/500 token，快速选择、拖拽、批量状态修改 | 对照 SDK 请求数、长任务、DOM 重建次数与实际拖拽观感；无关 token 变化不重新取/重绘当前 HP 面板。 |
| 开启中的功能立即关闭，再打开 | 最终运行状态与开关一致；失败不会假显示可用；同模块只有一套监听器。 |
| DM + 两名玩家 | Boss HP 一致，隐藏单位不意外公开；玩家指针不影响拖拽；各端转场各播放一次；迟加入恢复持久展示而不重放旧演出。 |
| 设置页输入中另一端改配置 | 草稿和焦点保留，保存针对正确条目；失败仍能继续修改，不静默恢复旧值。 |
| 明暗主题、窄窗口、减少动态效果 | 控件可见可点，透明层不遮黑，不出现不可关闭或阻断画布的残留层。 |
