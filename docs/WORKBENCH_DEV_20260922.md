## 行为

- 角色选择为顶部横向标签：可编辑的卡优先，同组内当前场景有绑定棋子的卡优先。未选中棋子仍显示卡；点击标签不修改场景选中状态，选中有效绑定棋子时切换。角色数据以 room/card ID 识别，不依赖单个棋子。
- 未锁定卡供其他玩家只读；锁定卡仅拥有者与 GM 可读。锁图标在编辑开关左侧；写入 scene/room 角色目录的 locked 与 visibility，后端命令每次复查角色与权限。旧 owners/dm 私有卡保持锁定。
- 修改整卡自动保存 schema 0.3 与原生快照，原武器/抗性保留。状态写入原状态 metadata；共享状态定义补充各客户端个人目录缺项，保留已有个人特效偏好。资源写入原资源 metadata。绑定同一角色的当前场景多个棋子一并更新。
- 快捷栏左边固定法术攻击/DC，下面原卡武器，伤害合并附加伤害；右边生命骰、法术位、契约位和自定义资源。次数/进度条/数值及原资源图标保留。职业更新只增加对应上限差额，不自动恢复已消耗部分。法术页与快捷栏的已用法术位互通。
- 数值支持空白草稿，失焦或 Enter 提交；空白/无效草稿恢复原值。普通模式禁止身份、技能训练和已学法术的破坏性拖拽；状态与预备法术保留战斗操作。

## 重连与同步边界

新链接 fragment 带独立 client capability，使用同源 /suite-dev/relay 的 HTTPS 长轮询；不要求 opener，支持右键直接拆分打开。宿主凭据保存在插件浏览器存储中，刷新后重新注册；客户端自动重连。保留直接窗口通信回退；旧版本的链接需要从更新后的 action 重新取得。

中继仅暂存内存队列，不落盘角色或骰子消息。宿主和客户端使用不同凭据，客户端凭据不能注册宿主。队列/请求/会话有限额。每个玩家建议保留一个工作台页面；同一链接的多个页面会争用同一客户端接收队列，暂不支持多页面同时编辑。链接是访问凭据，不应转发给其他玩家。

网页新版写入通过中继中的按 room/card 串行保存网关执行，比较最新 JSON 的 SHA-256 后调用既有角色 API；冲突返回错误，保留本地修改并要求重试。旧上传/导入客户端直接调用原 API 的写入不参与该串行队列，因此不宣称跨全部旧客户端的原子事务。Owlbear metadata 和 HTTP 文件是两个独立存储操作，也不构成跨系统事务。

锁定控制工作台阅读权限；原有静态 /characters/ 地址依然属于旧公开存储，已知文件地址不具备服务器级访问控制。真正的私密文件/头像需要下一步接入认证下载或签名 URL，不能把隐藏卡片当作文件加密。

## 头像存储建议

现有本地实现压缩为最长边不超过 1280、约 450 KB 以内的 WebP。建议在线头像保存为独立 room/card/avatar/<内容哈希>.webp，角色只同步 URL/hash 与 x/y/zoom，替换时上传新版本再原子切换引用，旧文件延迟清理；离线仍用 IndexedDB 缓存。头像上传/私密下载端点本轮没有实现，已有头像仍按原生文档保存。不要塞进房间 metadata（官方 room metadata 总额 16 KB）。
